# Update nudge

The card the app raises when a computer that runs work is connected on an older Infinitary than this computer's and the app could not update it by itself (`docs/devices.md`, "Updating by itself" and "The card that asks for it").
It is the host's own card with the Attention chip, never the first mate's, so its words are fixed and come from one shared module.

**Usually no card.**
A computer this computer can update with nothing asked of the person is updated as it connects, its running work paused for a moment and carried on after.
The feed alone says so: "Updating Infinitary on Mac mini." and then "Mac mini runs this computer's version of Infinitary now."
The card goes up only when the update asked a password there, did not go through, needs a new command run there, or is for a Windows PC, or when the person said Not now for that gap.

**Card.**
Meta: the computer's name ("Mac mini", "Running as Builder").
Title: "Update Infinitary on Mac mini".
First paragraph: both versions ("Mac mini has alpha 0.4.0-alpha.70.
This computer has alpha 0.4.0-alpha.75.") and what the gap costs, and only while it costs something.
While the computer takes no work it says "It takes no new work until it is updated.
Tasks for projects set to run there wait, and Automatic skips it.
Work already running there goes on."
While it still takes work it says "It still takes work.
Updating keeps the two in step."
Second paragraph: how Update it reaches it, over Remote Login with your own SSH key, over your network, or on this computer's own Infinitary for another user on this computer; its running work stops for a moment and goes on after.
A Mac a command added that downloads its update itself reads "It downloads this computer's version of Infinitary, or this computer sends its own copy over your network, with a count."
(`AddAMac.prompt.md`, "Updating any other computer").
A computer too old to update from here says "Its version of Infinitary is too old to update from here, so it needs a new command.", and its button reads Make the command.
After a refused update, the person's own or the one the app tried by itself, the card returns once with a third paragraph carrying the refusal.

**Buttons.**
Update it (default) opens Settings → Devices and the update runs on arrival, so the row reads "Updating Infinitary on Mac mini…".
For a joined Ubuntu package worker the update the app tried by itself went over the connection alone, and the card goes up as soon as the worker comes back unchanged from that update without being sent a copy; Update it tries the connection again, then the package route, with any address, confirmation or approval question under that worker's row (`DevicesTab.prompt.md`, "Another version").
Not now holds the card away until a version changes, and nothing updates that computer by itself for that gap.

**When.**
Once per gap, one feed line; it comes down by itself when the computer runs this computer's version.
The first mate's offer to update the same computer never makes a second card.
