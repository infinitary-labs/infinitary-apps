The project change card uses the setup card's host-owned shape, with Attention and first mate meta, no reply field, and the ordinary footer.
The app writes it from an exact proposed change, never from agent HTML.
The title asks “Change website?”, using the project’s current name.
The opening says that nothing changes until the captain clicks Apply change.
A table follows: Detail, Now, After your click.
It names each changed field in the same words as Settings, with data in mono, and shows the full hosting address rather than only its host.
The primary Apply change and ghost Not now are the only buttons; only Not now declines the proposal.
The shared minus puts the card aside and keeps the proposal pending, without applying or declining it.
Apply change rechecks the stored values, refuses a stale offer, and applies the exact patch once through Settings' dispatcher.
An address the app discovers in git always needs this card before it becomes the saved destination.

The move card is the same shape for moving repositories into another project.
The title asks “Move ledger-business and ledger-infra into ledger-app?”, or “... into a project of its own?”, one card per project they join.
The opening says that nothing moves until the captain clicks Apply move.
A table follows: Repository, Project now, After your click, each project with its key in mono, such as “ledger-app (LED)”.
Short paragraphs below say that each repository keeps its name, folder and settings; which open tasks join, by key in mono and title, and how many finished tasks follow, keys kept; how many automations move; that the project's directions then reach these repositories; and which projects leave the list, with “Nobody can take those keys again.”
The primary Apply move and ghost Not now are the only buttons, and Apply move refuses a card the projects changed under since it was written.
Its title, sentences, table headings and buttons read in the language the app speaks; repository and project names and keys stay as they are.

The Details group on a project's page in Settings holds labeled Scope, Folder and Where it lives inputs, followed by a small secondary Save details button; the project's Name has its own Save in the Project box above.
These use the existing Input, Button and setting-row primitives and their keyboard focus rings.
The folder description says to move it first and finish or drop its tasks; this control never moves files.
The hosting description says to enter the address the folder points at, or leave it empty for this computer.
Save details applies only the changed fields; an error stays beside the controls.
A project kept on this computer offers Local merge only, until its hosting address is approved.
The personal workspace has no detail controls.
