The Repositories panel on a project's page in Settings → Projects ends with a Remove line under Details, separated by the same hairline: a title naming the repository it removes, “Remove {name}”, the description “Takes it off this list.
Its folder and finished tasks stay.”, and a small danger Button, “Remove”.
The list and the personal workspace's page never carry it.

Remove first reads the tasks still on the project (any planned or working one).
If there are some, the line stays and says in danger text which, by key and title with their state, then “Finish or drop them, then remove it.”
Nothing is asked and nothing is written; it does not offer to drop them.
Otherwise the line turns into one question in place, “Remove {name}?
Its folder stays at {path}, and its finished tasks stay readable.”, with Cancel (secondary, focused, so Enter never removes) beside the danger Remove.
While it runs the button reads “Removing...”.
When done the project's page goes back to the list without it and the feed says “Captain · Project {name} · removed”.
Adding it back, by its address or by picking its folder, links the folder it left where it is instead of cloning a second copy, and makes a new project with a new key and default settings.
Remove is never the way to combine projects: moving a repository keeps its settings and its tasks' keys (`ChangeCard.prompt.md`, the move card, and the Move line just above, `MoveRepository.prompt.md`).
Removing never wakes the first mate.
