# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code. It holds only what almost every session needs; each line points to the doc under `docs/` that owns the detail.

## What this project is

Infinitary is an Electron desktop app: your own AI studio, a calm first mate and a crew of AI agents that work on the person's own computer and model subscriptions (Codex, Grok, Claude, OpenRouter, ...). Craftsmanship, not mass production: each task is scoped, done in its own working copy, checked, shown with evidence and recorded. The app needs no account or service of ours, and the person's work never passes through us. Product vision, interaction model, and constraints: `.claude/skills/infinitary-design/readme.md`.

## Principles (captain; full text in `docs/principles.md`)

- **Hide the machinery (2026-08-17).** Infinitary is the most advanced agent harness, but it aggressively hides that complexity from the end user. The user interacts with just the main first mate agent and a few settings - nothing else. The fewer concepts we expose, the better. The sign-in flow and the Subscriptions tab never expose the "harness" technicality - they speak only of providers, accounts (labeled by the user, except Claude, which follows its current identity), and quota; an e2e assertion enforces the wording.
- **Subscriptions (2026-09-24):** Supported subscriptions are only those that run through Pi; Claude is the sole exception.
- **The iOS app adds no feature the desktop app lacks (2026-10-25).** It may adapt how things work and where they appear, but anything new needs a deliberate design decision the captain approves first (`docs/ios.md`).
- **VoiceOver and accessibility work on the Infinitary iOS app are out of scope for now.** Agents must not reopen this work until the captain asks for accessibility improvement.
- **Center crew animation stays consistent across platforms.** Any change to the center crew animation must update the desktop app and the iOS app consistently in the same change.
- **Every feature works from the keyboard (2026-10-04).** A new control is reached with Tab, or the arrows inside a list, and draws the focus ring. An action a person repeats becomes a command in `KEYBOARD_COMMANDS`, so command search lists it; it gets a default key only where none clashes, and its control shows the key hint. An end-to-end journey drives it by keys (`docs/keyboard.md`, "A new feature").
- **Core primitives (2026-09-23, "Reuse the primitives you already have"):** before adding behavior, read `primitives/README.md` and the relevant contracts; reuse their owners rather than creating parallel systems.
- **Put ambiguous judgments in agent instructions (2026-09-23).** Deterministic logic is for closed, typed facts. Do not build a static parser that tries to understand natural language. The host carries what the agent declared; it does not infer the judgment by parsing the words or by guessing from structure.
- **Build the agent's reach, never its verdicts (2026-10-19).** The host hard-codes only a typed fact it holds, consent for an effect, or a physical limit; everything else - what a person meant, what should happen next, how much is enough - is a verdict the agent decides from the fact, the primitive and the goal, and a number, category or order the host made up is a verdict too. It governs the host's code and the instructions it serves: a new hold, cap, constant or served sentence answers which of the four it is (`docs/delivery-rigor.md`).
- **The two documents (F4c, F6b):** `DATA-TERMS.md`, `LICENSE` (Apache-2.0 + `NOTICE`) and `CONTRIBUTING.md` (no DCO) stay UNPUBLISHED until the public beta. A change to the terms is a new version of the file, never a silent edit; counsel reviews before publication (`docs/sharing.md`).
- **A test runs on the Mac only when it needs a Mac (2026-10-28).** Linux runs every test it can; edited unit-file rounds run locally even for portable files (INF-2273), while the full-check Mac lane runs only tests tagged `MAC_ONLY_TAG` (journeys) or listed in `scripts/mac-unit-tests.ts` (unit files), plus every journey in the run on `main` (`main.yml`); automatic alphas inherit that exact coverage. A lint and the Linux journey jobs hold the tag to what a test needs (`docs/principles.md`, `docs/testing.md` "Tests that need a Mac").

- **The captain decides and the fleet does the work (2026-10-22).** Never ask the captain to do what the fleet can do, including through a crewmate; check whether it is already done first. Ask only for the captain-only part, as one click where available; post-merge fleet work is a `Continue: …` filing (`docs/principles.md`, `docs/required-actions.md`).

## Design system (mandatory)

All UI work MUST follow the project skill `infinitary-design` (`.claude/skills/infinitary-design/`). It owns every visual and interaction rule: tokens, type, color, motion, components, character rendering, tone of copy. Never re-invent brand rules in code; if a rule is missing, extend the skill first, then implement. The package is offline-complete (fonts and mock runtime vendored; see its readme "Offline completeness").

- Tokens: `.claude/skills/infinitary-design/tokens/*.css` - consume these, never hardcode values they define.
- Click-through mock: serve the skill dir over HTTP, open `ui_kits/firstmate/index.html` (voice states trigger on a real right-⌥ keydown).

## The green gate and tests (`docs/testing.md`)

- **Focused proof, not duplicate gates (INF-2259):** the PR's Linux check owns typecheck, lint/adherence and build; opening it may start required proof, which must finish for the current version before merge. Portable journeys run in Linux CI; every edited Vitest file gets three total local runs, including portable files (INF-2273); admitted explicit Mac-required journeys may run locally even in CI mode, with build through cleanup under one load declaration. Edited test files run three total rounds, ordinary coverage plus two more, with no retries and first-failure stopping; Mac-listed unit files keep those three rounds on Mac. Full local journey suites remain prohibited. Full pre-merge verification is exceptional, never justified by breadth, confidence or care level alone (`docs/testing.md`, "When to request full verification").

- **New journeys follow the six words** (`docs/testing.md`, "This project's rulings on tests"): a new end-to-end journey is written under the same six-word rule as any other test, with no ask, and its review names the promised result, the data, the completion signal, the platform prerequisites and the shared resources (FI3-1732).
- **Weakening or deleting a test is ask-first** (`docs/testing.md`, "This project's rulings on tests"): weakening, skipping or deleting an existing test waits for the captain's approval. Otherwise the crew's default rule on tests decides which tests are written and how a failing one is repaired (`docs/delivery-rigor.md`, "The default rule on tests").
- **A change's own tests are never flakes** (`docs/testing.md`, "This project's rulings on tests", INF-840/INF-2259): edited journeys run three total rounds per required platform, every edited Vitest file runs three total rounds locally, and edited phone parts three on each device; ordinary proof is included. Portable journeys use Linux CI; every edited unit file runs locally under the declared load, selected native journeys use the admitted Mac route, and complete phone selections use CI. The crew never calls its edited tests suspected flakes; `check_change` records its evidence-backed judgment.
- Before merge, the PR's `typecheck-lint-build` check and relevant focused e2e proof cover what changed, without a duplicate complete local pre-push gate (through their CI route in CI mode; locally, run a `renderer`/`application` lane spec alone with `--no-deps`, or it runs the whole serial `desktop` lane). Full unit, integration and probe sweeps run on main and in release verification, not on pull requests; the full e2e suite runs in `verify.yml`'s mac and `linux-e2e` lanes and `pnpm package:mac` in its mac lane (rolling main, manual alphas without reusable proof, and named full-run exceptions). The full e2e suite runs only in CI, never locally during development or release preparation; request it through `github_write` as described in `docs/forge.md` ("Verification workflow requests"). The full unit suite is not a per-push obligation.
- **Route the requested scope** (`docs/testing.md`, "When to request full verification"): all Linux proof means `source-journeys.yml` with `suite: full`, exact source commit, requesting task and reason: the existing eight groups, no Mac tests, signing or packaging. Manual `verify.yml` full-system requests explicitly select `full_system: true` and record task/source/reason under a named exception; neither profile is Linux-only. Inspect existing same-source checks, including running ones, before dispatching duplicate work. Linux-only proof never substitutes for main/release full-system proof; reusable callers and separate installer routes keep their coverage.
- **Where the heavy checks run** (`docs/testing.md`, "Where the heavy checks run"): required proof follows the hybrid owners above, not one place for every check. A computer with `git config infinitary.checks` = `ci` runs journeys, the phone check, the replay gate, the typecheck and the lint only through CI: those commands refuse outside CI and name their route on request (`journeys.yml` with `files`, `phone.yml`, `replay.yml`, the pull request's `typecheck-lint-build` check). Small unit diagnostics and pictures stay local in both modes; the admitted selected-native route is an explicit exception, and inside CI these checks always run.
- The PR checks are `ci.yml`'s Linux baseline job, `typecheck-lint-build`, and its `linux-startup` fixtures job; edited unit-file rounds run locally for every file, never in extra PR repeat jobs (INF-2273). Full `unit-tests`, both `integration-tests` shards and `probe-tests` run only on request; a push to `main` starts no `ci.yml` job, since the full check's `linux-checks` lane (`verify.yml`) runs the same commands with every probe, and releases run every cohort through `verify.yml` (INF-2340; `docs/test-cohorts.md` "Probes", `docs/testing.md`). Journey selections through 40 files run in full; larger selections request `source-journeys.yml` with `suite: full` on the exact source, never a hand-pruned subset (INF-2394 measure 2).
  Keep the selector's `--ran` listed-versus-run record with successful run evidence; tagged tests still need native proof (`docs/testing.md`, "Journeys on the pull request").
  A pull request runs no journeys and no phone check (INF-2139, captain: "let's pull journeys and phone checks off PRs now"): a crewmate runs the journeys its change reaches (`node scripts/affected-journeys.ts --base origin/main` lists them) and, for phone files, the phone check itself, locally or, in CI mode, by requesting `journeys.yml` with `files` and `phone.yml` with `affected` (`docs/testing.md` "Journeys on the pull request", "The phone check on request"). Every push to `main` that changes more than the phone app or the docs runs `main.yml`, the full check with every journey, queued and never cancelled, and no phone check, which runs every part before each phone release (`ios-release.yml`, INF-2492), with no run-alone pass, which runs with the proof of edited journeys (`scripts/journey-runs.ts`); its newest passing run is main's green mark (`docs/testing.md`, "The continuous run on main"). Automatic alphas inherit every journey from their exact successful rolling-main source; manual alphas without reusable proof still run every journey. CI green means every check on the exact head SHA is completed/success or completed/skipped; never treat an old SHA as authoritative for the current head.
- **A new e2e test reads frames, keys, saved data and words through their owners** (`docs/e2e-contracts.md`): a frame through `tests/e2e/frames.ts` (`cardBody`, `panelBody`, `bodyIn`), focus through `focusOn` and `pressKey`, saved data after a launch through `readSavedData`, the words it expects from the module that owns them ("Words come from their owner"); four lints in `pnpm check` refuse the raw forms.
- **A journey's own stand-in behavior is a scenario** (`docs/testing.md`, "A journey's own scenarios"): a scripted model behavior a few journeys need goes in its own file under `tests/e2e/scenarios/`, named where the journey starts its stand-in (`launchApp({ scenarios })`), never in the shared `mockProvider.ts`; a lint in `pnpm check` refuses a scenario import anywhere but a journey or another scenario.
- **Each test owns its prerequisites** (`docs/testing.md`): a named test must work alone from fresh state. An intentionally ordered journey is one test with named sections, never separate tests borrowing a predecessor's state.
- **Pictures of a visible change** (`docs/testing.md` "Capturing pictures of a change", `docs/card-authoring.md`): photograph each changed view before the first edit and again after it, through the hermetic launcher; the merge card's Before and After show them, as many as the change needs. Behavior a still cannot show gets a demo recording instead (`startDemo`, `docs/testing.md` "Recording a demo").
- A timing claim in a test is an ORDER or WORK, never a wall-clock window (captain's B1: "one clock, budgets measured"). Budgets go through `tests/e2e/perf.ts`; a lint refuses `toBeLessThan(X_MS)` elsewhere in `tests/e2e`.
- Temp directories only through `scratchDir(prefix)` (`tests/helpers/scratchDirs.ts`), never at module scope or in a Playwright `describe` body; await work that writes after a test returns. Leftovers fail the run.
- Vitest cohorts (captain's A1; `docs/test-cohorts.md`): `pure`, `unit` (in memory, 5 s default) and `integration`, whose files that can fail with no code change run as `probe`. A test that spawns must be listed as integration with a measured budget; never raise a unit test's timeout instead.
- E2E is hermetic and windowless (`tests/e2e/launch.ts`, `docs/e2e-contracts.md`): throwaway userData and HOME, `PI_OFFLINE=1`, a mock provider and a mock Claude client. Never let a test or probe start a real Claude sign-in - it reaches the captain's browser (`docs/claude-client.md`). On macOS a test pins the app's home with `CFFIXED_USER_HOME` and never boots into the real folders.
- **The statement check** (`docs/testing.md`, "The statement check"; INF-2061): every SQL statement the app prepares in the vitest projects is planned on a freshly migrated database, and a whole-table walk or temporary sort of a growing table fails its test file unless the shrink-only ledger `tests/helpers/statementWalks.ts` explains it; answer a new walk with an index or a seeking query.

- **A main repair labels its own PR `fixes-main`** (`docs/testing.md`, "A main repair's priority label"; INF-1423): a crewmate repairing a failing main adds the label to its own main-targeted PR once it has recorded the failure, and removes it on withdrawal. - A PR touching the prompt, card lint, the whose-turn sort, routing, the first mate agent, or `src/renderer/src/cards/` runs `pnpm replay:gate` before pushing (`replay.yml` on request in CI mode); the baseline moves only in a PR that explains every moved number (`docs/replay-harness.md`).

## Credentials, quota and accounts

- Infinitary never reads a provider token; sign-ins live in per-account stores owned by `AccountVault`. The first mate flagship rebinds only at attachment points, never mid-turn (`docs/architecture.md` §16).
- Quota honesty (`docs/quota.md`): unknown is never zero; only a 401 (never a 403) triggers renewal; `auth_required` ("sign in again") only from proof - a provider-refused refresh token or a 401 that survived a real renewal, never Claude's saved expiry date. A no-window fallback is never a success. An unreadable store is `unknown`, never a sign-out.
- `src/shared/quotaSignals.ts` is the one home of quota math (clean-room to quota-axi semantics; never depend on or copy quota-axi). "Ahead" is the warn state.
- The Claude client is the one the person installed (F14: "assume / require the user has already installed claude code cli"); the app ships and downloads none (`docs/claude-client.md`). A rule that must reach a Claude crewmate or the first mate on Claude lives in a tool description under 2,048 chars or a top-level parameter, never only a nested one.
- Reading a project's pull request history: a `/pulls` page overruns `github_read`'s 256 KiB answer and comes back as a smaller page, so list `/issues` (it carries pull requests) and follow each answer's `nextPath`, a `/repositories/{id}/...` path; for file-level work, fetch `refs/pull/<n>/head` and replay in git (`docs/forge.md`, "Reading a project's pull request history").

## The first mate, crew and cards

- The orchestrator contract (`docs/orchestrator-contract.md`): the first mate holds typed tools only - no bash, no file reads; reading is a crewmate's job. A redline is a contract revision: add one file to `src/core/prompts/contract-revisions/` (its README says how); `FIRSTMATE_CONTRACT_VERSION` counts them and is never written by hand.
- The first mate's turns are steer-only, a captain KEEP call (`docs/architecture.md` §2).
- Answer delivery (`docs/task-capture.md`): each captain message is checked for one action that took effect after the first mate read it - never for whether the answer is right. One output-only retry (the typed `answer-missing` wake, mutation tools refused), then one task-less notice (`card-ask-<id>`, Ask again or Leave it); the saved state lives on `captain_asks`, and closing words are never a card.
- Whose turn (`docs/report-sort.md`, captain's C7 A "heuristics only"): a report is sorted in code from typed state, never by reading its prose; every idle crewmate, whatever left it idle, is read by one reconciler on a durable clock (the idle ladder), whose only trigger is a missing witness, never a named situation. The sort and the ladder read one witness set (`IdleLadder.witnesses`), and a task's gate is one of them (`primitives/tasks.md`). Every steer and wake rides the durable inbox (`docs/inbox.md`); a wake carries new information or it does not fire, and a provider failure spends no delivery attempt (the honest retry).
- A provider-failed turn must stay a `turn_failed` event; auth classification lives only in `src/shared/authFailure.ts`, never substring matching. The first mate's turn ends with brief output - never empty, never the exact token `done` (`docs/firstmate-runaway-hardening.md`).
- Sessions are durable and nothing prunes them (captain: "we shouldn't remove the entire session JSONL altogether").

Commit subjects and pull request titles use `type(scope): summary` or `type: summary` (optional `!` and `BREAKING CHANGE` footer). Use `feat`, `fix`, `chore`, `test`, `refactor`, `docs`, or `perf`; scopes are open-ended (for example `cards`, `crew`, `e2e`, `main`). `feat`, `fix`, and breaking changes drive release versions; never mislabel a fix as a feature. The host checks new subjects and pull request titles before opening or merging and squashes GitHub pull requests using the checked title.

## Delivery (`docs/delivery-rigor.md`)

- Delivery direct-pr (captain rule): a crewmate that opens a PR babysits CI until every check on the head SHA is green before its final report; the first mate never presents a land/merge/accept decision while CI is red or running.
- Care is three recorded names, quick / standard / reviewed (Quick, Default, Careful): the host records and selects guidance by them and holds nothing else on a name; what each asks is the care runbook's (`resources/runbooks/care`, `docs/runbooks.md` "Built-ins"). Standard is every repository's default, and a task with no gate to land through takes no care. Reports carry five headings in order: Intent, What changed, Verified, Risk, Not done. Every new branch-based change and its completion card share one saved story: public GitHub/GitLab carry native attachments, other description hosts carry text, and plain/local branches keep it on the card; existing PRs predating stories retain the five-heading description (`docs/forge.md`, "Saved change stories"). Failed checks are diagnosed first; three unsuccessful own repairs exhaust the allowance, while evidenced baseline waits and one reserved flake rerun spend nothing (`docs/delivery-rigor.md`).
- Every hold is one entry of `HOLDS` (`src/shared/holds.ts`), soft or fixed; a site cites its kind through `overridePasses`, `softHoldWords` or `fixedHoldWords`, the captain's words pass a soft hold as one recorded override the first mate declares, and `pnpm check` (`scripts/holds.ts`) refuses a hold outside the registry (`docs/delivery-rigor.md`, "The holds").
- Every named limit (a `const` whose name holds `MAX`, `MIN`, `CAP`, `LIMIT`, `BUDGET`, `CEILING` or `FLOOR`) is in `scripts/limits.ts` with what it rests on and its way out; `pnpm check` refuses one it lacks, and its baseline of made-up numbers only shrinks (`docs/agents-reach.md`).
