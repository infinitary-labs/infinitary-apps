受付ラウンドは、新しい Issue やプルリクエストなど、ほかの人があなたのプロジェクトに書いたものを読み、それぞれにどう対応するかを下書きするタスクです。
Infinitary にすでにある部品、つまり自動化、読むだけの乗組員、あなた自身の言葉の方針から組み立てます。
GitHub、GitLab、Bitbucket で、Infinitary がプロジェクトの置き場所に届くプロジェクトならどれでも使えます。

## 予定どおりラウンドを始める {#start-a-round-on-a-schedule}

1. **設定** を開き、**自動化** を開いて、**新しい自動化** を選びます。
2. **タイミング** で、実行する頻度を選びます。
3. **プロジェクト** で、対象のプロジェクトを選びます。
4. **一等航海士に伝えること** に、あなたのやり方を書きます。
   何を読むか、各項目をどう判断するか、簡単な返信がどういうものかです。
5. 確認してオンにするには **オンにする…** を選びます。

たとえば「前回のラウンド以降に開かれたか返信があった Issue とプルリクエストを、読むだけの乗組員で読んで。それぞれに返信を下書きし、簡単な返信ごとに投稿するタスクを始めて。」のように書きます。

## 読む乗組員 {#the-crewmate-that-reads}

Issue やプルリクエストの文章は誰からでも来うるので、ラウンドは読むだけの乗組員としてそれを読みます。
読んだものはすべて情報として扱い、指示としては扱いません。
この乗組員が送りたいものは、方針が何を言っていても、1 枚の承認カードであなたを待ちます。
[誰でも書ける文章を読む乗組員](/ja/integrations/#a-crewmate-that-reads-words-anyone-can-write)を参照してください。

## 簡単な返信をクリックなしで送る {#let-plain-replies-go-without-your-click}

あなたが自分の言葉で認めたとき、返信はカードなしで送られます。

1. どの返信を確認なしで送ってよいかを書いた、プロジェクトの方針を一等航海士に伝えます。
   たとえば「受付ラウンドの送信タスクは、受付のやり方にはっきり沿った返信を投稿してよい。それ以外は何もしない。少しでも変わったものやあいまいなものは、私のクリックを待つ。」のように伝えます。
2. あなたのやり方の中で、下書きした返信ごとに専用のタスクを始めるよう一等航海士に頼みます。
   そのタスクは返信を投稿するだけで、知らない人の文章は読みません。
3. 返信が方針の範囲にはっきり入るとき、そのタスクの乗組員は方針を名指しして、カードなしで 1 回だけ投稿します。
   変わっていると判断した返信や、方針の範囲に入らない返信は、カードであなたのクリックを待ちます。

Infinitary が確かめるのは、方針がまだ有効であることだけです。
今の言い回しをあなたから聞いていて、廃止されていないことです。
返信があなたの言葉で認められたものかどうかは、乗組員が判断します。
同じ作業のカードであなたがすでに出した許可でも、同じように返信が送られます。
[方針に従う人](/ja/knowledge/#who-follows-a-direction)を参照してください。

## これからもあなたを待つもの {#what-still-waits-for-you}

- 読む乗組員が自分で送るものすべて。
  方針が何を言っていても待ちます。
- 連携を通した変更。
  その規則は **設定** → **連携** のままです。
- 別のプロジェクトへの変更。
- マージ。
  マージカードからしか行われません。

## 送られたものを見る {#see-what-went-out}

カードなしで投稿された返信は、そのタスクの **アクティビティ** に 1 行を加え、よりどころにしたあなたの言葉を引用します。
結果がわからない返信は二度と送られません。
届いたかどうかは、プロジェクトの置き場所でその項目を読んで確かめてください。

## 止める {#stop-it}

返信が自動で送られないようにするには、方針を廃止するか変えるよう一等航海士に伝えます。
それ以降、返信はどれもまたあなたのクリックを待ちます。
ラウンドそのものを止めるには、**設定** → **自動化** で、その自動化の **一時停止** を選びます。
