受理轮次是一个任务，它阅读别人在你的项目上写的内容，例如新的议题和拉取请求，并为每一项起草该怎么处理。
你用 Infinitary 已有的部件来搭建它：一项自动化、一个只读的船员，以及一条用你自己的话写成的指引。
它适用于 Infinitary 能在其所在之处访问到的任何项目，无论是在 GitHub、GitLab 还是 Bitbucket 上。

## 按计划开始一轮 {#start-a-round-on-a-schedule}

1. 打开“**设置**”，然后打开“**自动化**”，并选择“**新建自动化**”。
2. 在“**时间**”下，选择它多久运行一次。
3. 在“**项目**”下，选择它所关于的项目。
4. 在“**告诉你的大副**”下，写下你的方法：读什么、如何判断每一项，以及简单的回复是什么样子。
5. 选择“**打开…**”来检查并打开它。

例如：“用一个只读的船员，阅读自上一轮以来新开或有新回复的议题和拉取请求。为每一项起草回复，并为每条简单的回复开始一个发布它的任务。”

## 阅读的船员 {#the-crewmate-that-reads}

议题和拉取请求中的内容可能来自任何人，所以这一轮以只读船员的身份阅读它们。
它把读到的一切都当作信息，从不当作指示。
无论指引怎么说，它想发送的任何东西都会在一张批准卡片上等你决定。
请参阅[读取任何人都能写的内容的船员](/zh-hans/integrations/#a-crewmate-that-reads-words-anyone-can-write)。

## 让简单的回复无需你点击就发出 {#let-plain-replies-go-without-your-click}

当你用自己的话说过可以时，回复就能不经卡片发出。

1. 告诉你的大副一条项目指引，说明哪些回复可以不问就发出。
   例如：“受理轮次的发送任务可以发布明确遵循我们受理方法的回复，除此之外什么都不做；任何奇怪或含糊的内容都等我点击。”
2. 在你的方法中，请大副为每条起草的回复单独开始一个任务，由它发布回复，并且不读陌生人的任何内容。
3. 当一条回复明显属于你的指引所涵盖的范围时，该任务的船员会注明你的指引，不经卡片发布一次。
   它觉得奇怪的回复，或你的指引没有涵盖的回复，会在卡片上等你点击。

Infinitary 只检查你的指引是否仍然有效：它当前的措辞是从你那里听到的，并且没有被停用。
一条回复是否属于你的话所允许的范围，由你的船员判断。
你已在同一项工作的卡片上给出的同意，也会让回复以同样的方式发出。
请参阅[谁会遵循指引](/zh-hans/knowledge/#who-follows-a-direction)。

## 仍会等你的事 {#what-still-waits-for-you}

- 阅读的船员自己发送的任何东西，无论指引怎么说。
- 通过集成进行的更改，它保留“**设置**” → “**集成**”中的规则。
- 对另一个项目的更改。
  在 GitHub、GitLab 或 Bitbucket 上没有项目的任务改用你的 GitHub 登录，这时你的同意可以让更改发到任何仓库。
- 合并，它只通过合并卡片进行。

## 查看发出了什么 {#see-what-went-out}

每条不经卡片发布的回复都会在其任务的“**动态**”中添加一行，引用它所依据的你的话。
结果未知的回复绝不会再次发送；请在项目所在之处阅读该项，看看它是否已送达。

## 停止 {#stop-it}

要让回复不再自行发出，请告诉你的大副停用或更改这条指引。
从那以后，每条回复都会再次等你点击。
要停止这一轮本身，请在“**设置**” → “**自动化**”中对它的自动化选择“**暂停**”。
