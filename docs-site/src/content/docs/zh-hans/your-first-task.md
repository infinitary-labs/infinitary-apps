本页从头到尾跟随一个请求。
它假定你已连接订阅并添加了项目。
如果还没有，请先从[首次启动](/zh-hans/first-launch/)开始。

## 1. 说出你想要什么 {#1-say-what-you-want}

在窗口底部的消息框中输入你的请求，然后发送。
像对一个人提要求那样写：你想要什么，以及对你重要的事。
例如：“在网站上，让注册按钮在手机上更显眼。”
[你可以请求什么](/zh-hans/what-you-can-ask-for/)展示了更多种类的请求。

你也可以用说话代替输入，或添加图片和文件。
请参阅[大副](/zh-hans/the-first-mate/)。

## 2. 大副接下请求 {#2-your-first-mate-takes-it}

你的消息会出现在消息框的正上方。
在它下面，大副的标记会在“处理中…”旁边旋转，直到它的回复取而代之。
回复是一句简短的话，说明它做了什么，例如开始了一个任务。

它自己能回答的问题，会以卡片的形式回来。
针对你的项目的工作会成为一个任务，带有类似 `WEB-12` 的任务编号，并由一名船员开始处理。
每个请求都会在窗口右侧的任务中得到一条记录。

## 3. 船员完成工作 {#3-a-crewmate-does-the-work}

船员在你的项目的独立工作副本中工作，所以你自己的文件保持原样。
工作时，它会围绕窗口中央的大副转动。
关于它正在做什么的简短条目，会出现在左侧的动态中。

你不需要一直盯着。
想看更多，可以从任务中打开这个任务，或把指针停在船员上。
请参阅[任务和船员](/zh-hans/tasks-and-crewmates/)。

如果船员需要你做决定，它会送来一张卡片。
对于较大的请求，这张卡片可能是一份计划，在它动手构建之前等你同意。
回答它，船员就会继续。

## 4. 合并卡片 {#4-the-merge-card}

当工作完成并检查过后，船员会送来一张合并卡片。
它是这次改动的完整说明：

- **原因**，一句话。
- **改了什么**，几条简短的要点。
- 改动涉及的每个界面的 **之前** 和 **之后** 图片。
- 船员检查了什么，以及怎么检查的。
- 卡片右上角一幅关于这次改动风险的小图。

点击图片可以放大查看。
把指针停在风险图的某个点上，可以读到它评估的是什么以及原因。
关于如何阅读卡片，请参阅[卡片和决定](/zh-hans/cards-and-decisions/)。

## 5. 合并它 {#5-merge-it}

阅读卡片，然后选择：

- **合并拉取请求** 会在你的项目托管处合并这次改动。
  对于保存在这台电脑上的项目，按钮显示 **合并分支**。
- **仔细审查**（针对拉取请求）会先要求一次独立审查。
  审查通过后，会送回一张新的合并卡片。
- **丢弃** 会放弃这项工作。

如果检查仍在运行，按钮显示 **检查通过后合并**。
点击它，Infinitary 会在检查一通过就合并。
如果检查未通过，按钮显示 **修复错误后合并**。
点击它，Infinitary 会在错误修复且检查通过后合并。

想改为提出修改，请在卡片中显示“还有要补充的吗？”的输入框里输入，然后点击 **聊天**。
船员会在卡片旁的讨论中回答，并在完成后更新卡片。

## 6. 合并之后 {#6-after-the-merge}

任务关闭，并在任务中移到“完成”。
它的记录保留了你提出的要求、改了什么、证据，以及你做出的决定。

如果这次改动在合并后需要只有你才能做的事，合并卡片会在顶部“合并之后，你需要……”下说明。
请参阅[卡片和决定](/zh-hans/cards-and-decisions/)。

## 不询问直接合并 {#merging-without-asking}

项目在你另行说明之前，会在合并前先询问。
要让完成的工作在通过检查后自动合并，请在设置 → 项目中为该项目关闭 **合并前先询问**。
合并之后，你仍会收到一张带有这次改动说明的卡片。
