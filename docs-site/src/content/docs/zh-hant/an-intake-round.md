受理輪次是一項任務，它會閱讀別人在你的專案上寫的內容，例如新的議題和 pull request，並為每一項草擬該怎麼處理。
你用 Infinitary 已有的部件來組成它：一項自動化、一位只讀的船員，以及一項用你自己的話寫成的指引。
只要 Infinitary 能在專案所在之處連到它，不論是在 GitHub、GitLab 還是 Bitbucket 上，都能使用。

## 按排程開始一輪 {#start-a-round-on-a-schedule}

1. 打開 **設定**，再打開 **自動化**，然後選擇 **新增自動化**。
2. 在 **時間** 底下，選擇它多久執行一次。
3. 在 **專案** 底下，選擇它相關的專案。
4. 在 **告訴你的大副** 底下，寫下你的方法：要讀什麼、如何判斷每一項，以及簡單的回覆長什麼樣子。
5. 選擇 **開啟…** 來檢查並開啟它。

例如：「用一位只讀的船員，閱讀自上一輪以來新開或有新回覆的議題和 pull request。為每一項草擬回覆，並為每則簡單的回覆開始一項發布它的任務。」

## 閱讀的船員 {#the-crewmate-that-reads}

議題和 pull request 裡的內容可能來自任何人，所以這一輪會以只讀船員的身分閱讀它們。
它把讀到的一切都當作資訊，從不當作指示。
不論指引怎麼說，它想送出的任何東西都會在一張核准卡片上等你決定。
請看 [讀取任何人都能寫的內容的船員](/zh-hant/integrations/#a-crewmate-that-reads-words-anyone-can-write)。

## 讓簡單的回覆不必你點按就送出 {#let-plain-replies-go-without-your-click}

當你用自己的話說過可以，回覆就能不經卡片送出。

1. 告訴大副一項專案指引，說明哪些回覆可以不問就送出。
   例如：「受理輪次的發送任務可以發布明確遵循我們受理方法的回覆，除此之外什麼都不做；任何奇怪或含糊的內容都等我點按。」
2. 在你的方法裡，請大副為每則草擬的回覆另外開始一項任務，由它發布回覆，而且不讀陌生人的任何內容。
3. 當一則回覆明顯在你的指引涵蓋範圍內，那項任務的船員會註明你的指引，不經卡片發布一次。
   它覺得奇怪的回覆，或你的指引沒有涵蓋的回覆，會在卡片上等你點按。

Infinitary 只檢查你的指引是否仍然有效：它目前的文字是從你那裡聽到的，而且沒有被停用。
一則回覆是否在你的話所允許的範圍內，由你的船員判斷。
你已在同一項工作的卡片上給過的同意，也會讓回覆以同樣的方式送出。
請看 [誰會遵循指引](/zh-hant/knowledge/#who-follows-a-direction)。

## 仍會等你的事 {#what-still-waits-for-you}

- 閱讀的船員自己送出的任何東西，不論指引怎麼說。
- 透過整合進行的變更，它保留 **設定** → **整合** 裡的規則。
- 對另一個專案的變更。
  在 GitHub、GitLab 或 Bitbucket 上沒有專案的任務改用你在 GitHub 的登入，這時你的同意可以讓變更送到任何存放庫。
- 合併，它只透過合併卡片進行。

## 查看送出了什麼 {#see-what-went-out}

每則不經卡片發布的回覆，都會在它任務的 **動態** 裡加上一行，引用它所依據的你的話。
結果不明的回覆絕不會再次送出；請在專案所在之處閱讀那一項，看看它是否已送達。

## 停止 {#stop-it}

要讓回覆不再自己送出，請告訴大副停用或更改這項指引。
從那之後，每則回覆都會再次等你點按。
要停止這一輪本身，請在 **設定** → **自動化** 裡對它的自動化選擇 **暫停**。
