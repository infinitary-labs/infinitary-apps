作業手冊是大副和船員針對某種工作遵循的書面指引，例如規劃一項變更、教一堂課，或為提交命名。
它裡面是文字、範例和圖片，不會在你的電腦上執行任何東西。
Infinitary 內建一些作業手冊，你也可以製作或加入更多。

## 作業手冊在哪裡 {#where-runbooks-live}

打開 **設定**，再打開 **作業手冊**。
你也可以在指令搜尋裡搜尋 **開啟作業手冊**。

這個部分有三個群組：

- **內建** 列出 Infinitary 附帶的作業手冊。
- **你的** 列出你加入的，或你和大副一起製作的作業手冊。
- **自己製作** 有 **你的作業手冊資料夾**，以及可以怎麼提出要求的範例。

每一列都會顯示作業手冊的名稱、用途和它的開關。

## 開啟或關閉作業手冊 {#turn-a-runbook-on-or-off}

用作業手冊的開關來開啟或關閉它。
你也可以請大副幫忙，例如「關閉課程」。

大副做完手上的事之後就會照新的設定做，之後開始的每位船員也一樣。
已經在工作的船員，會沿用它開始時的指引。

關閉的作業手冊不會引導任何人，但它會留在清單裡，所以你可以再把它打開。

## 內建作業手冊 {#the-built-in-runbooks}

大多數內建作業手冊一開始就是開啟的。
有四份一開始是關閉的，直到你開啟它們：**批次 pull request**、**pull request 留言**、**心跳** 和 **進階架構**。

- **常用工作流程**：大副如何進行規劃、建置、修正和研究。
- **交付判斷**：對於經由 pull request 進行的工作，船員如何判斷檢查、修復，以及變更何時可以合併。
- **測試規則**：船員規劃或變更專案時要測試什麼。
- **謹慎度等級**：每個等級對變更的要求：**快速**、**預設** 和 **謹慎**。
  請看 [謹慎度](/zh-hant/tasks-and-crewmates/#rigor)。
- **提交與 PR 命名**：提交、pull request 和工作分支如何命名。
  關閉它、而且你也沒有為它們命名的作業手冊時，Infinitary 不會檢查任何名稱。
- **程序**：對於可以用腳本拆分的工作，船員會寫一段簡短的腳本，把每個部分排成一項獨立的任務。
- **休閒專案**：大副如何設定好玩或個人用的小專案。
  請看 [你可以請它做什麼](/zh-hant/what-you-can-ask-for/#a-small-project-for-fun)。
- **課程**：跨好幾天學習一門學科的指引和卡片元件。
  請看 [你可以請它做什麼](/zh-hant/what-you-can-ask-for/#a-subject-learned-across-days)。
- **批次 pull request**：把你核准的變更合在一起，成為一個批次 pull request，讓它們的檢查只跑一次。
  開啟它之後，就能在設定 → **專案** 裡為某個專案選擇批次 pull request。
  請看 [專案](/zh-hant/projects/#how-changes-reach-your-project)。
- **pull request 留言**：船員會回答它的 pull request 上的留言，直到合併為止。
  明確的修正它會自己做，不明確的則會當成選擇交給你。
- **心跳**：當有工作開始等待卻沒有任何東西提起它，或是安靜了很久之後，大副會檢視等待中的工作，推動它繼續或問你一次。
  它會帶來一個自動化，你可以在設定 → **自動化** 裡暫停它；關閉這份作業手冊就會移除它。
- **電腦清理**：在你同意後進行一次只讀取的檢視，並用一張卡片讓你選擇要停止哪些殘留的東西。
  請看 [你可以請它做什麼](/zh-hant/what-you-can-ask-for/#a-look-at-a-computer-under-strain)。
- **移入機密**：船員如何把機密從另一個工具移入 **機密**，而不讓任何代理看到任何一個值。
  船員只會在進行這類移動時讀它。
  請看 [機密](/zh-hant/secrets/)。
- **意見回饋**：在任何訊息框輸入 `/feedback` 和幾句話，船員會為 Infinitary 的開發者起草一個議題，由你閱讀並親自發布。
  它包含 App 和系統的相關事實，從不包含你的名字、路徑或專案。
- **進階架構**：畫出專案的各個部分以及它們如何連接，並顯示一項變更在這張圖上動到了什麼。
  它還在實驗階段。

當某個專案正在使用批次 pull request 時，Infinitary 不會讓你關閉 **批次 pull request**，並會寫出是哪個專案。

## 閱讀作業手冊 {#read-a-runbook}

按內建作業手冊旁邊的 **檢視**。
它會打開這份作業手冊在你電腦上的資料夾的唯讀副本。
想改變內建作業手冊的運作方式，請像下面那樣請大副把它變成你的。

## 自己製作 {#make-your-own}

用你自己的話請大副幫忙。
設定裡的 **自己製作** 有一些範例，例如：

- 「讓每位船員都有一項用淺白文字撰寫版本說明的技能。」
- 「做一份作業手冊，告訴大副我喜歡簡短的回答。」

船員會在 **你的作業手冊資料夾** 裡寫下新的作業手冊。
它會列在 **你的** 底下並立刻開啟，除非你要求它一開始是關閉的。

**開啟資料夾** 會在你的電腦上打開 **你的作業手冊資料夾**。
在那裡修改作業手冊，會像切換開關一樣傳到大副和船員那裡。

## 把內建作業手冊變成你的 {#make-a-built-in-runbook-yours}

請大副複製一份內建作業手冊，例如「複製常用工作流程，讓它一律先規劃再建置。」

1. 大副會把整份作業手冊用新的名稱複製到 **你的作業手冊資料夾**。
2. 這份副本會列在 **你的** 底下，一開始是關閉的，所以目前什麼都不會改變。
3. 自己修改這份副本，或請大副修改它。
4. 開啟這份副本。
   內建的那份會同時關閉。

內建作業手冊會保持原樣。
想改回去，就關閉你的副本，再開啟內建的那份。

## 加入別人分享的作業手冊 {#add-a-runbook-someone-shared}

請大副從某個網址或資料夾加入作業手冊，例如「加入別人分享的這個網址或資料夾裡的作業手冊。」

在你回答它的卡片之前，什麼都不會加入；卡片的標題會帶有作業手冊的名稱，例如「要加入版本說明嗎？」。
卡片會寫出這份作業手冊來自哪裡、誰製作的、它能觸及什麼，以及它會關閉哪些內建作業手冊。

- **加入** 會加入這份作業手冊並開啟它。
- **不要加入** 會拒絕它，並刪除已經擷取的內容。

你擱到一旁的卡片，會讓這個提議繼續等著。
已加入的作業手冊有更新時，會用同一種卡片再問你一次。

想移除已加入的作業手冊，就請大副依名稱移除它。
被它關閉的內建作業手冊，會保持關閉，直到你再次開啟它。

**你的** 裡 Infinitary 無法讀取的作業手冊，會顯示原因，沒有開關，在修好之前不會引導任何人。

## 從另一台電腦 {#from-another-computer}

在從別處控制大副的電腦上，開關會更改大副所在電腦上的作業手冊。
**檢視** 和 **開啟資料夾** 只能在那台電腦上使用，資料夾那一列也會寫出它的名稱。
請看 [你的其他電腦](/zh-hant/your-other-computers/)。

## 使用鍵盤 {#use-the-keyboard}

Tab 可以移到每個 **檢視** 按鈕和開關。
指令搜尋裡有 **開啟作業手冊** 和 **開啟你的作業手冊資料夾**，你可以在設定 → **鍵盤** 裡為其中任何一個設定按鍵。
請看 [鍵盤](/zh-hant/keyboard/)。
