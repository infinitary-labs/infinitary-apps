你的大副和船員透過你已經有的 AI 訂閱方案工作。
你可以在設定的 **智慧等級** 底下，於 **AI 訂閱方案** 清單裡管理它們。

## 加入訂閱方案 {#add-a-subscription}

1. 打開設定，選擇 **智慧等級**。
2. 在 **AI 訂閱方案** 底部的 **新增帳號** 底下，選擇你的供應商：Codex、Grok、Claude、Kimi Code、Copilot、OpenRouter 或 Amazon Bedrock。
3. 依照供應商的要求登入。
   有些會打開你的瀏覽器，有些會顯示一組要在它們網站上輸入的代碼，有些則要你貼上一組金鑰。
4. 登入完成後，新的帳號會出現在清單裡。

同一個供應商可以加入不只一個帳號。
這時它的按鈕會顯示像是 **再加入一個 Codex 帳號** 這樣的字。

## 為帳號命名 {#name-your-accounts}

每個帳號都有一個標籤，讓你分得出個人帳號和工作帳號。
如果登入時沒有帶出帳號名稱，會打開一個名稱方塊讓你輸入。
之後想更改，可以打開帳號的選單並選擇 **重新命名**。

Claude 帳號不太一樣。
它會跟隨你電腦上 Claude Code 的登入，所以它那一列會顯示目前在那裡登入的人。
它沒有 **重新命名**，如果你切換 Claude Code 的登入，那一列也會跟著改變。

每個帳號都會為它供應商的每一種額度顯示一個小量表，例如每次對話和每週。
數字是還剩多少。
把指標停在量表上，就能看到它何時重設。

- 當你用得比時間快時，長條會變成琥珀色：以這個速度花用，撐不到重設的時候。
- 數字低於一半時會變成琥珀色，低於五分之一時會變成紅色。
- 量表旁邊會用一個詞總結這個帳號：**剛好**、某段時間 **後用完**，或 **已用完**。
- **截至 3 小時前** 表示最後一次讀數已經是舊的，所以它的數字會變暗。
- 破折號表示那項額度沒有讀取到。
- 持有 [已儲存的重設](#saved-codex-resets) 的 Codex 帳號，會在量表下方顯示有幾次。

清單頂端的 **重新整理** 會重新讀取每一項額度。
Infinitary 不會讀取 OpenRouter 或自訂 API 的額度，那一列也會說明這件事。
Amazon Bedrock 依用量向你的 AWS 帳號計費；它那一列會根據 Infinitary 記錄的工作，顯示本月的估計金額。

## 選擇哪個帳號做什麼 {#choose-which-account-does-what}

打開帳號的選單（它那一列上的三個點），就能看到這些選擇。
設定排在最前面，每一項都有一個開關顯示它是否開啟；選擇一項即可開啟或關閉，選單會保持開啟。

- **優先用於船員工作** 會讓船員優先使用這個帳號。
  它會標上 ✱。
- **已暫停** 的開關打開時，這個帳號上的所有工作都會停止。
- **中斷連結** 會把這個帳號從 Infinitary 移除。

當大副使用的供應商有兩個以上的帳號時，設定會讓你選擇大副要用哪一個來回答。
那個帳號會標上 **大副** 標籤。

## 額度用完時 {#when-an-allowance-runs-out}

你的船員會自己繼續下去。
新的工作會交給還有額度的模型。
如果那個等級已經沒有額度了，船員的工作會改用較弱的模型，或等到額度重設。

當大副自己的帳號用完時，它會先換到同一個供應商、還有額度的另一個帳號。
如果沒有，會出現一張寫著 **你的大副已用完它的額度** 的卡片。
你的話會先等著，什麼都不會遺失。
在卡片上，你可以選擇 **重新檢查額度**、把大副換到另一個供應商，或 **開啟設定**。
如果重新檢查沒有發現變化，卡片也會提供再試一次供應商的選項，例如 **Try Claude again**，用於大副透過另一個登入連到供應商的情況；如果額度仍然用完，它會再次暫停。

有些供應商可以用你在它們那裡設定的點數繼續回答。
對於 Claude 或 Codex 帳號，選單裡有 **用點數繼續**。
這時船員只會在用完每一項包含的額度後才花用點數。
Infinitary 絕不會購買點數，也不會設定點數的上限；這些都在供應商自己的網站上處理。

### Codex 已儲存的重設 {#saved-codex-resets}

ChatGPT 可以給 Codex 帳號一些已儲存的重設。
每一次重設，都能在額度自行重設之前把它補滿。
帳號那一列會顯示它有幾次，以及要在哪裡使用，例如「1 次已儲存的重設 · 在 chatgpt.com 使用」。

只要現在有一次可以使用，帳號的選單裡就會有 **使用已儲存的重設**。
說明額度已用完的那張卡片也會這樣告訴你，並附上同一個按鈕，以及通往 chatgpt.com 用量頁面的連結。
接著 Infinitary 會讓你電腦上的 Codex 使用最先到期的那一次重設。
這需要 Codex 0.143 或更新版本，而且第一次使用時，Codex 會請你登入那個 ChatGPT 帳號。
用掉的重設無法再拿回來。
「動態」會說明發生了什麼事，以及還剩幾次。

不必等你按下按鈕，Infinitary 也可以自己使用它們。
在帳號的選單裡，或在那張卡片上，開啟 **自動使用已儲存的重設**；在你開啟之前，它是關閉的。
這時 Infinitary 只會在有工作等待、又沒有任何帳號還有額度可用時才使用一次，而且只在等額度自己補滿要等很久的時候。
還有額度的帳號永遠優先。
它每使用一次，「動態」都會說明。

## 重新登入 {#sign-in-again}

登入可能會失效。
失效時，帳號那一列會顯示 **重新登入**，並出現一個 **登入** 按鈕。
選擇它，然後像第一次那樣登入。
這會更新同一個帳號，它的標籤和選擇都會保留。

## 自訂 API {#custom-api}

如果你的組織自己執行 AI 伺服器，請在 **新增帳號** 底下選擇 **自訂 API**。
為它取一個名稱，填入伺服器的位址、需要的話再填入金鑰，以及要使用的模型。
**儲存** 會在船員能使用之前檢查每個模型。
接著你可以在 **模型** 看板上，選擇船員是否使用這些模型。

### 來自檔案的連線 {#connections-from-a-file}

如果你已經把連線存在一個採用 Pi 的 `models.json` 格式的檔案裡，Infinitary 可以從這個檔案讀取它們。
在 **AI 訂閱方案** 底下的 **連線檔案** 那一列，按 **選擇檔案**，然後挑選那個檔案。
Infinitary 只會讀取這個檔案：絕不會變更它，也絕不會使用寫在裡面的金鑰。

檔案定義的每個連線都會出現，並標示 **來自你的檔案** 和 **尚未核准**。
按 **核准**，輸入這台電腦自己的金鑰，以及檔案沒有寫明的模型大小，然後按 **儲存**，它會檢查每個模型。

之後 Infinitary 會跟隨這個檔案。
新的名稱或價格會立刻套用，上限有變更時則會重新檢查那個模型。
位址、通訊協定或標頭有變更時，連線會暫停，直到你按 **重新核准**。
從檔案裡消失的連線會暫停，絕不會刪除。
**停止讀取** 會停止跟隨這個檔案，你核准過的連線則會保留。

### 在你的其他電腦上 {#on-your-other-computers}

當另一台電腦替你執行工作時，自訂連線的那一列會提供 **使用**，並註明是哪一台電腦。
你要輸入那台電腦自己的金鑰，它會檢查每個模型，並自己保存這把金鑰；這台電腦不會留下副本。
之後對這個連線的變更，也會跟著套用到那裡。
請看 [你的其他電腦](/zh-hant/your-other-computers/)。

## 用量 {#usage}

設定 → **用量** 會顯示大副和船員在所有專案中用了多少。
它一開始會以 **估計 $** 顯示；在 **用量顯示為** 底下，你可以切換成 **Token**。
選擇要計算的 **期間** 和 **工作** 的種類。
估計的美元金額是價值的參考，不是帳單。

**每個任務的成本** 會用圖表呈現一項已完成的任務花了多少，包含它的審查在內。
每個點是在它之前七天內完成的任務的中位數，色帶則涵蓋其中的中間一半。
線條上升，表示任務比以前需要更多工作。
**專案** 和 **類型** 可以把範圍縮小到你想比較的工作。

**最近的任務** 會列出每項任務用了多少。

在 **智慧等級** 底下，**任務花費超過此金額前先問過你** 可以設定一個金額。
超過這個金額的任務，會在一個安全的時間點停下來，先用卡片問過你，才會再花用。

## 長對話 {#long-conversations}

對話變長時，你的大副和船員會摘要它，並從摘要繼續，這樣每則訊息花費更少，對話也仍放得進模型。
在 **智慧等級** 底下，**長對話在此處摘要** 可以設定在哪裡摘要。

- **自動** 在 300,000 個 token 時摘要；若模型在更低的位置開始加價，就提早摘要。
- **150,000 個 token**、**200,000 個 token**、**300,000 個 token** 或 **500,000 個 token** 在這個數字摘要；若模型本身的上限更小，就在其上限處摘要。
- **各模型本身的上限** 只在接近各模型本身的上限時才摘要，可能多達一百萬個 token。

數字越低花費越少；數字越高，完整保留的對話越多。
當你選的數字讓某個模型超過請求開始加價的位置時，這一列會列出該模型和那個位置。
已經開著的對話從下一則訊息起依照變更，在你的其他電腦上也一樣；與 Claude 的對話在下次開始時依照變更。
