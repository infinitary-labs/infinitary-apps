這一頁從頭到尾跟著一個請求走。
這裡假設你已經連接訂閱方案，也已經加入專案。
如果還沒有，請從 [第一次啟動](/zh-hant/first-launch/) 開始。

## 1. 說出你想要什麼 {#1-say-what-you-want}

在視窗底部的訊息框輸入你的請求，然後送出。
就像拜託一個人那樣寫：你想要什麼，以及任何你在意的事。
例如：「在網站上，讓註冊按鈕在手機上更容易看到。」
[你可以請它做什麼](/zh-hant/what-you-can-ask-for/) 列出更多種類的請求。

你也可以用說的代替打字，或加上圖片和檔案。
請看 [大副](/zh-hant/the-first-mate/)。

## 2. 大副接手 {#2-your-first-mate-takes-it}

你的訊息會出現在訊息框正上方。
在它下面，大副的標誌會在「處理中…」旁邊轉動，直到它的回覆取代那個位置。
回覆是一句簡短的話，說明它做了什麼，例如開始一項任務。

它自己能回答的問題，會以卡片的形式回來。
你專案上的工作會變成一項任務，帶有像 `WEB-12` 這樣的編號，並由一位船員開始處理。
每個請求都會在視窗右側的「任務」裡留下一筆紀錄。

## 3. 船員動手做 {#3-a-crewmate-does-the-work}

船員在它自己的專案工作副本裡工作，所以你自己的檔案會保持原樣。
它工作時，會繞著視窗中央的大副轉。
關於它正在做什麼的簡短文字，會出現在左側的「動態」裡。

你不需要一直盯著。
想看更多，可以從「任務」打開那項任務，或把指標停在船員上。
請看 [任務與船員](/zh-hant/tasks-and-crewmates/)。

如果船員需要你做決定，它會帶來一張卡片。
如果請求比較大，那張卡片可能是一份計畫，等你同意後才開始建置。
回答它，船員就會繼續。

## 4. 合併卡片 {#4-the-merge-card}

工作完成並檢查過後，船員會帶來一張合併卡片。
它是這項變更的完整說明：

- **為什麼**，用一句話說明。
- **變更了什麼**，用幾個簡短的重點列出。
- 變更碰到的每個畫面的 **之前** 和 **之後** 圖片。
- 船員檢查了什麼，以及怎麼檢查。
- 卡片右上角一張描繪這項變更風險的小圖。

點按圖片可以放大。
把指標停在風險圖的某個點上，就能看到它評估的是什麼，以及原因。
想進一步了解怎麼讀卡片，請看 [卡片與決定](/zh-hant/cards-and-decisions/)。

## 5. 合併它 {#5-merge-it}

讀完卡片後，選擇：

- **合併 pull request** 會在專案所在處合併這項變更。
  如果專案放在這台電腦上，按鈕會顯示 **合併分支**。
- **仔細審查**（在 pull request 上）會先要求一次獨立審查。
  審查通過後，會再送回一張新的合併卡片。
- **捨棄** 會放棄這份工作。

如果檢查還在執行，按鈕會顯示 **檢查通過後合併**。
點按它，檢查一通過，Infinitary 就會合併。
如果檢查未通過，按鈕會顯示 **修正錯誤後合併**。
點按它，等錯誤修正、檢查通過後，Infinitary 就會合併。

如果你想改為要求修改，請在卡片上顯示「還有要補充的嗎？」的欄位裡輸入，然後按 **聊天**。
船員會在卡片旁的討論串裡回答，完成後再更新卡片。

## 6. 合併之後 {#6-after-the-merge}

任務會結束，並移到「任務」裡的「已完成」。
它的紀錄會保留你要求了什麼、變更了什麼、證據，以及你的決定。

如果這項變更合併後還需要只有你能做的事，合併卡片會在頂端的「合併之後，你需要…」底下說明。
請看 [卡片與決定](/zh-hant/cards-and-decisions/)。

## 不經詢問就合併 {#merging-without-asking}

在你另外指定之前，專案都會在合併前先問過你。
如果想讓完成的工作在通過檢查後就合併，請在設定 → 專案裡，為那個專案關閉 **合併前先問過你**。
合併之後，你仍然會收到一張附上變更說明的卡片。
