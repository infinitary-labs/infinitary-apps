# Languages

The app's own words come from one catalog, written in English first, with one file per language.
A compiler turns the catalog into one typed function per message, and every function answers in the language the process speaks.
Dates, times, numbers, money and plural forms go through one module, so they follow the same language.
English is the source and the fallback: a message a language lacks shows in English.

Words the captain or the crew wrote, names, saved values and ids are never translated.
"Infinitary" is never translated.

## The language fact

`src/shared/i18n/languages.ts` holds the rules every process shares, and imports nothing.

- `resolveLanguage(preferred, available)` picks the catalog language that best matches a computer's own languages, most preferred first.
  It tries each preferred language in turn: first a catalog language with the same script and, when the catalog language names a region, the same region (`zh-TW` finds `zh-Hant`), then one with the same script alone (`pt-PT` finds `pt-BR`).
  Nothing matching means English, and a pseudo-language is never picked this way.
- `textDirection(tag)` says which way a language's text runs, from its likely script: Arabic, Hebrew, Persian and Urdu run right to left.
- `languageFormatTag(tag)` is the locale a language's own numbers and money are written in: `en-US` for English, as the app has always written them.

`src/shared/i18n/current.ts` holds the language the process speaks.
A process that never sets it speaks English.

- The main process sets it once the app is ready, from Electron's `app.getPreferredSystemLanguages()` (`startLanguage` in `src/shared/i18n/start.ts`).
- A window learns it from its preload's argument (`languageArgument`), as it learns its material and its desktop.
  The preload marks it on the document as `lang` and `dir` before the first paint, and the page sets its own process's language from `lang` before its first render (`src/renderer/src/app/language.ts`).
- A frame, such as a panel's, does not yet learn the language: the frame bridge carries a theme but no language.

No stored language choice exists yet: the app follows the computer, and the crew is not yet told the captain's language.

## The catalog

`src/shared/i18n/messages/en.json` is the English source; a translation is `messages/<tag>.json`, such as `zh-Hans.json` or `pt-BR.json`.
A catalog is one JSON object of messages by name.
A name is camelCase and says where the words show, such as `fileCancel`.

A message is a string, or one string per plural form:

```json
{
  "fileCancel": "Cancel preparing {name}",
  "composerLines": { "plural": "count", "one": "{count} line", "other": "{count} lines" }
}
```

- `{name}` is a placeholder the caller fills with a string; `{{` and `}}` write a brace.
- `plural` names the number that picks the form, and that number is written in the language's own digits and grouping (`formatNumber`).
  Each language gives exactly the forms its plural rules use, read from the runtime's own `Intl.PluralRules`: English `one` and `other`, Arabic all six, Japanese `other` alone.
- Any other number a message shows reaches it as a string the caller wrote with `formatNumber`.

After changing a catalog, run `pnpm generate:messages`, which writes `src/shared/i18n/messages.generated.ts`.
Never edit that file by hand.
Code reads a message by calling its function:

```ts
import * as m from "@shared/i18n/messages.generated";

m.fileCancel({ name });
m.composerLines({ count });
```

A word object a module already exports keeps its shape: a fixed word becomes a getter that calls the message, so it is worded when it is shown and follows a language change (`FILE_WORDS` in `src/shared/composer.ts`).

The crewmate that changes an English message writes every language's version in the same pull request.

### Why the project compiles its own catalog

The compiler is `scripts/generate-messages.ts`, a few hundred lines of the project's own.
Paraglide JS was the first choice, but its JSON format is a plugin module its project settings load, by default from a CDN, and its compiler brings the inlang SDK and about ten packages with it.
The project's compiler reads the same kind of JSON files, needs no network or package, and writes a file that imports only its siblings, so any part of the app, and a plain Node script, can use it with nothing added at run time.

## The pseudo-languages

Two made-up languages are compiled from the English catalog, never written by hand.

- `en-XA` brackets every message, accents every letter and lengthens the words by about a third: `[Åðð ƒîļéš ~~~]`.
  Text with no brackets skipped the catalog, and text cut off would be cut off in a longer language.
- `ar-XB` writes each run of words right to left and runs the window right to left, so a layout that assumes left to right shows.

A pseudo-language keeps English's plural forms and the locale of its base language.

## Formats

Every place the app writes a date, time, number or amount for a person goes through `src/shared/i18n/format.ts`:

| Function | Writes | In English |
| --- | --- | --- |
| `formatNumber` | a count or amount | US forms: `1,234` |
| `formatUsd` | US dollars | `$12`, `$12.50` |
| `formatDate`, `formatTime`, `formatDateTime`, `dateTimeFormat` | a date or time | the computer's own forms, as a bare `toLocaleString` call writes them |
| `formatLanguageDate`, `formatLanguageDateTime` | a date where the app always wrote US forms | US forms: `Oct 5, 3:12 PM` |
| `pluralCategory` | which plural form a count takes | `one` or `other` |

In any other language every one of them writes that language's own forms.
English keeps exactly what the app wrote before, so a change through this module changes nothing a person sees in English.

## What stays English

- Everything served to a model: the guidance, tool descriptions, tool answers and refusals.
  A count in served text goes through `servedNumber`, and a date through `SERVED_LOCALE`, so it reads the same whatever the captain's language.
- The project documents, logs, raw error text, the data exporters and the developer-only Observe view.
- Key names such as ⌘, Ctrl and Shift.

## The checks

`pnpm check` runs both:

- `node scripts/generate-messages.ts --check` refuses a catalog that is not JSON, a message name or placeholder that is not camelCase, a translation that lacks a message or holds one English does not, a translation whose placeholders or count differ from English, a plural message without exactly its language's forms, a hand-written pseudo-language, and a compiled file out of step with the catalogs.
- `node scripts/locale-formats.ts` refuses, outside `src/shared/i18n/`, a fixed `"en-US"` and a `toLocaleString`, `toLocaleDateString`, `toLocaleTimeString` or `Intl` formatter handed no locale, `[]`, `undefined` or a fixed tag.
  Reading `Intl.DateTimeFormat().resolvedOptions()` is allowed: it formats nothing.
  The few places that cannot follow the language are listed in the script with why, and the list only shrinks.
