# Languages

The app's own words come from one catalog, written in English first, with one file per language.
A compiler turns the catalog into one typed function per message, and every function answers in the language the process speaks.
Dates, times, numbers, money and plural forms go through one module, so they follow the same language.
English is the source and the fallback: a message a language lacks shows in English.

Words the captain or the crew wrote, names, saved values and ids are never translated.
"Infinitary" is never translated.

## The language fact

`src/shared/i18n/languages.ts` holds the rules every process shares, and imports nothing.

- `resolveLanguage(preferred, available)` picks the catalog language that best matches a computer's own languages, most preferred first.
  It tries each preferred language in turn: first a catalog language with the same script and, when the catalog language names a region, the same region (`zh-TW` finds `zh-Hant`), then one with the same script alone (`pt-PT` finds `pt-BR`).
  Nothing matching means English, and a pseudo-language is never picked this way.
- `textDirection(tag)` says which way a language's text runs, from its likely script: Arabic, Hebrew, Persian and Urdu run right to left.
- `languageFormatTag(tag)` is the locale a language's own numbers and money are written in: `en-US` for English, as the app has always written them.

`src/shared/i18n/current.ts` holds the language the process speaks.
A process that never sets it speaks English.

- The main process reads the computer's own language once the app is ready, from Electron's `app.getPreferredSystemLanguages()`, starts in the default language for it (`startLanguage` and `defaultLanguage` in `src/shared/i18n/start.ts`, "The default language"), and moves to the captain's choice as soon as the saved settings are read ("The language choice").
- A window learns that default language from its preload's argument (`languageArgument`), as it learns its material and its desktop.
  The preload marks it on the document as `lang` and `dir` before the first paint; once the saved look is read, the page speaks the captain's choice and marks it on the document (`followLanguage` in `src/renderer/src/app/language.ts`).
- A frame, a card's or a panel's, is born with the app's language as its document's `lang` and `dir`, and the locale its dates take as `data-locale` (`buildFrameDocument` and `buildPanelDocument` in `src/shared/plugins/frameDocument.ts`, "Dates and times").
  A panel document's boot module sets the frame lib's language from that `lang` before the panel draws, so the shared parts the lib serves (`@infinitary/ui`) speak it.
  A language change mounts frames anew; the frame bridge carries no language of its own.
- A run that is not the packaged app may name its language in `INFINITARY_LANGUAGE`, a pseudo-language included, such as `INFINITARY_LANGUAGE=en-XA` to find words that skipped the catalog (`languageOverride` in `src/shared/i18n/start.ts`).
  It stands in for the computer's own language, so a saved choice still wins over it, and a real language there is not spoken while English is the default; a pseudo-language always is.
  The packaged app ignores it.
  Every hermetic test start names `en` (`hermeticEnv` in `tests/e2e/launch.ts`), so a journey reads English whatever its runner's computer asks for, and a spec names another language in its own `env`.

## The language choice

Settings → Appearance ends with a Language row: the default, then every translation, each named in itself (`ownLanguageName`).
The default saves nothing.
While English is the default it reads English (default); once the app follows the computer it reads Follow this computer, naming the computer's language, and English joins the translations.
On a view the row says it sets only this window's words, since the crew follows the first mate's computer.
A language the keyboard steps to in the closed picker, as the arrow keys do on Linux, is a draft until Enter or leaving the picker applies it; a pick from the picker's open list applies at once.

### The default language

English is the default until every word a person reads is in the catalog, "Words still typed in the code" empty.
Only an explicit choice in the row switches the language meanwhile, whatever the computer asks for.
`FOLLOWS_COMPUTER` in `src/shared/i18n/start.ts` says whether the default is the computer's own language instead, and `tests/raw-words.test.ts` holds it to the ledger: the pull request that empties the ledger turns it on.

- The choice is the appearance's optional `language` (`src/shared/preferences.ts`), kept in a settings row of its own so an older build still reads the rest of the look (`docs/saved-data-compatibility.md`, "The language choice").
- `chosenLanguage(choice, computer)` is the one rule: the choice when the catalog has it, otherwise the default language, so a choice a newer build saved falls back to the default here.
- The core speaks the saved choice from the moment its settings open, before boot recovery and the first mate's inbox word anything (`src/core/services.ts`).
- The main process follows the saved look as it changes (`src/main/app.ts`), so the crew's language and every word the main process writes move with it.
- A view from before the choice reads the look strictly, so the home leaves `language` out of the look it pushes or answers there (`lookFor` in `src/core/connection/cardCompatibility.ts`, `src/shared/contract-changes/language-choice.md`).
- The window follows the same choice live: `LanguageRoot` mounts the window anew under the new language, and the Language row keeps Settings open on Appearance and takes its focus back when it applied the change (`notePickerChange`).
- A window in a language other than English says under the row, on a line of its own, that some parts of Infinitary still show English, until "Words still typed in the code" is empty.

## The shipped languages

The catalog holds English and nine translations: Simplified Chinese (`zh-Hans`), Traditional Chinese (`zh-Hant`), Japanese (`ja`), Korean (`ko`), Spanish (`es`), French (`fr`), German (`de`), Portuguese as written in Brazil (`pt-BR`) and Arabic (`ar`), the first language that runs right to left.
Each has a glossary in the design skill (`.claude/skills/infinitary-design/copy/glossary/<tag>.md`): its register, its typography and one word for each term of the Vocabulary.

### Translating

The crewmate that changes an English message writes every language's version in the same pull request, following each language's glossary, and adds a term the glossary lacks to it.
A translation keeps every placeholder of the English and gives exactly the plural forms its language uses; the compiler refuses one that does not ("The checks").

### The macOS language list

macOS lists an app's languages, in System Settings under the app's own language and in its menus and dialogs, from the `.lproj` folders in its bundle.
`electron-builder.yml`'s `mac.electronLanguages` keeps only the catalog's languages, by macOS's own folder names (`zh_CN` for `zh-Hans`, `zh_TW` for `zh-Hant`, `pt_BR` for `pt-BR`), and `tests/release-contract.test.ts` holds the list to the catalog.
Chromium picks its own locale from those folders, so a computer that prefers a language the bundle lacks, such as English (UK) or Swedish, gets US forms from a bare date call; "Dates and times" says how English avoids that.
While English is the default, the Language row, not System Settings, switches the app's language.

### Typefaces for every language

Space Grotesk and JetBrains Mono draw Latin, Greek and Cyrillic letters only.
For Chinese, Japanese, Korean and Arabic the type tokens name this computer's own typeface for that script after the brand faces, by the document's `lang` (`:lang()` in `tokens/typography.css`), so Latin words keep the brand face and the rest takes the script's face rather than a guess.
Those languages set tracking to zero: it spaces out glyphs that are already evenly set, and breaks the joins between Arabic letters.

### Adding a language

1. Add `messages/<tag>.json` with every message, and its glossary in the design skill.
2. Add the language's macOS folder name to `mac.electronLanguages`.
3. Add a typeface stack to `tokens/typography.css` when Space Grotesk does not draw its script.
4. Run `pnpm generate:messages`; the Settings row lists the language with no other change.

## The crew's language

The first mate and every crewmate write to the captain in the language the app speaks on the computer where the first mate lives, and keep the project's own language for what is read where the project lives.

- `CARD_AUTHORING` (`src/core/prompts/cardContract.ts`) says, to both: write cards, replies and reports in the captain's context-named language, unless the captain asks otherwise.
  To a crewmate it adds that commits, pull requests, change stories, code and its comments, and the project's documents keep the project's own language, the one its existing commits and documents use.
- The fact it reads is `captainLanguageFact` (`src/core/prompts/captainLanguage.ts`), the language named in English with its tag, such as `Simplified Chinese (zh-Hans)`: the first mate's context block carries it as `captain_language` each turn, and a crewmate's prompt names it when its session opens.
  A pseudo-language is a test's window, so under one the crew is told English.
- The merge card's four headings are catalog messages (`cardHeadingWhy`, `cardHeadingWhatChanged`, `cardHeadingBefore`, `cardHeadingAfter`).
  The card check accepts each heading in English or in the language the app speaks, and a crewmate's prompt lists the translated headings once the catalog has them.
  A saved story keeps the host's English outline, since it is read where the project lives.
- The served guidance itself stays English: only the language's name and the translated headings are added.

## The catalog

`src/shared/i18n/messages/en.json` is the English source; a translation is `messages/<tag>.json`, such as `zh-Hans.json` or `pt-BR.json`.
A catalog is one JSON object of messages by name.
A name is camelCase and says where the words show, such as `fileCancel`.

A message is a string, or one string per plural form:

```json
{
  "fileCancel": "Cancel preparing {name}",
  "composerLines": { "plural": "count", "one": "{count} line", "other": "{count} lines" }
}
```

- `{name}` is a placeholder the caller fills with a string; `{{` and `}}` write a brace.
- `plural` names the number that picks the form, and that number is written in the language's own digits and grouping (`formatNumber`).
  Each language gives exactly the forms its plural rules use, read from the runtime's own `Intl.PluralRules`: English `one` and `other`, Arabic all six, Japanese `other` alone.
- Any other number a message shows reaches it as a string the caller wrote with `formatNumber`.

After changing a catalog, run `pnpm generate:messages`, which writes `src/shared/i18n/messages.generated.ts`.
Never edit that file by hand.
Code reads a message by calling its function:

```ts
import * as m from "@shared/i18n/messages.generated";

m.fileCancel({ name });
m.composerLines({ count });
```

A word object a module already exports keeps its shape: a fixed word becomes a getter that calls the message, so it is worded when it is shown and follows a language change (`FILE_WORDS` in `src/shared/composer.ts`).
A sentence with parts that change is one message with placeholders, never pieces glued together, and a count's own words are one plural message.
Items joined as one list go through `formatList`.
A keyboard command's label and its other search words are messages, the search words one string separated by commas (`KEYBOARD_COMMANDS` in `src/shared/keyboard.ts`); in another language command search also finds a command by its English words (`inLanguage` in `src/shared/i18n/current.ts`).

### The app's own panels

An app panel (`src/panels/<id>/`) runs in its own frame and may import only React, `@infinitary/ui` and files in its own folder, so it cannot read `messages.generated.ts`.
Its messages stay in the same catalogs, named with the panel's prefix: `activityPanel`, `automationPanel`, `knowledgePanel` or `nowPanel`, followed by a capital letter or digit (`APP_PANEL_PREFIXES` in `scripts/generate-messages.ts`).
The compiler writes them to the panel's own `src/panels/<id>/messages.generated.ts` instead of the shared file, and that module carries its own number formatting and plural rules.
It reads the language from the frame's `<html lang>`, which the window sets before the panel's module loads, so a panel's words are worded in the language the frame opened in.
`pnpm generate:messages --check` checks these files too, and the compiler removes a panel's module once it has no messages.

### Why the project compiles its own catalog

The compiler is `scripts/generate-messages.ts`, a few hundred lines of the project's own.
Paraglide JS was the first choice, but its JSON format is a plugin module its project settings load, by default from a CDN, and its compiler brings the inlang SDK and about ten packages with it.
The project's compiler reads the same kind of JSON files, needs no network or package, and writes a file that imports only its siblings, so any part of the app, and a plain Node script, can use it with nothing added at run time.

## The pseudo-languages

Two made-up languages are compiled from the English catalog, never written by hand.

- `en-XA` brackets every message, accents every letter and lengthens the words by about a third: `[Åðð ƒîļéš ~~~]`.
  Text with no brackets skipped the catalog, and text cut off would be cut off in a longer language.
- `ar-XB` writes each run of words right to left and runs the window right to left, so a layout that assumes left to right shows.

A pseudo-language keeps English's plural forms and the locale of its base language.

## Saved facts

A line the app saves and shows later is saved as a fact, so it is worded in the language of whoever shows it, when it is shown, and a line written before a language change follows it.
`src/shared/i18n/said.ts` owns the shape.

- A fact names a catalog message and what fills its blanks: `{ m: "settleMergingChange", a: { change: "PR #61" } }`.
- A fill is a string shown as it is (a name, a key, words the captain or the crew wrote), a count, a time of day (`{ time }`, worded where it is shown) or another message with its own fills, one level deep.
- `said(name, fills)` builds one, its fills checked against the message's own blanks; `saidLine` gives a line its fact and the fact's English.
- Every saved line keeps its English `text` beside its `said` fact, for a reader that words nothing itself, such as the phone today, and for a fact a later catalog cannot word: `wordedLine` and `wordSaid` fall back to the English.
- Activity saves the fact in `activity_events.said_json`, and a task's note keeps it in its data (`said`, and `lineSaid` for a merged close); the window words each line as it reads the feed.
- A run of the app's own words inside a card body is one element whose only content is the fact's English, with the fact on `data-inf-said` (`saidMark`); the window words each run when it draws the body (`wordSaidBody`) and moves the card's change bars with it.
- A body the app wrote whole, the welcome, is marked `data-inf-app-body="welcome"`; the window draws `welcomeBody()` in its own language in its place, and titles it the same way (`appBodyOf`, `wordedTitle` in `src/shared/welcome.ts`).
- A line the first mate's computer says of itself saves this computer and here as places (`PLACE_SAID`), which a computer that controls it fills with its name and words again (`placesAs`); one it still renamed this computer in after that keeps those words and drops its fact (`namedHere`).

The app menu and the tray menu are built from the catalog and built again when the language changes (`onLanguageChange`).
The native file dialogs are worded when they open.

Not every saved line is a fact yet: host notice cards, most first mate notes and some device and project lines still save English alone and show it in every language.

## Formats

Every place the app writes a date, time, number or amount for a person goes through `src/shared/i18n/format.ts`:

| Function | Writes | In English |
| --- | --- | --- |
| `formatNumber` | a count or amount | US forms: `1,234` |
| `formatUsd` | US dollars | `$12`, `$12.50` |
| `formatDate`, `formatTime`, `formatDateTime`, `dateTimeFormat` | a date or time | the computer's own forms, in its preferred locale ("Dates and times") |
| `formatLanguageDate`, `formatLanguageDateTime` | a date where the app always wrote US forms | US forms: `Oct 5, 3:12 PM` |
| `pluralCategory` | which plural form a count takes | `one` or `other` |
| `formatList` | items as one list | `a, b and c`, with no comma before the last word |

In any other language every one of them writes that language's own forms.

### Dates and times

In English, dates and times name the computer's own preferred locale, the first of `app.getPreferredSystemLanguages()`, outright (`regionalLocale` in `src/shared/i18n/current.ts`).
The packaged Mac app keeps only the shipped languages' folders, so the runtime's own default locale is US English on a computer that prefers English (UK) or Swedish, and a bare call would write US forms there.
The main process sets the locale where it starts (`setComputerLocale`), and hands it to a window's page as an argument (`localeArgument`), which the preload marks on the document and the page reads with its language (`followLanguage`).
A frame's document names the same locale as `data-locale` (`FRAME_LOCALE_ATTRIBUTE` in `src/shared/plugins/frameDocument.ts`), the computer's in English and the language's otherwise.
A panel frame's boot module hands it to the lib's own copy of this module (`src/renderer/src/frameRealm/entries/boot.ts`), so the shared parts it serves write dates as the window does, and a frame program that formats a date itself hands it to each date call it makes.
Numbers and money in English keep the US forms the app always wrote; dates and times the main process writes, which were always US forms, now take the computer's own too.

## What stays English

- Everything served to a model: the guidance, tool descriptions, tool answers and refusals.
  A count in served text goes through `servedNumber`, and a date through `SERVED_LOCALE`, so it reads the same whatever the captain's language.
- The project documents, logs, raw error text, the data exporters and the developer-only Observe view.
- Key names such as ⌘, Ctrl and Shift.

## Words still typed in the code

The window (`src/renderer/src/`), the app's own panels (`src/panels/`) and the keyboard commands' words (`src/shared/keyboard.ts`) move into the catalog area by area.
`scripts/raw-words.ts` reads each of their files and counts the runs of words typed in for a person to read: JSX text, a string in an attribute a person reads such as `aria-label` or `title`, and any other string that reads as prose.
A string compared in code, used as a key, a selector, an event or a style, or handed to an `Error` or `console` is not counted.

The files that still hold raw words are on its ledger, `RAW_WORDS_LEDGER`, with how many runs each holds, and the ledger only shrinks:

- a file not on the ledger holds none;
- a listed file may not gain one;
- a listed file that lost some lowers its count, or leaves the ledger at none, in the same pull request.

Words that must stay typed in say why with `i18n-exempt: <reason>` in a comment on their line or the line above, which covers the statement or expression starting there: a product name, a key name, or text that is not shown.
`node scripts/raw-words.ts --show <file>` lists one file's raw words, and `--list` every file's count.
The ledger is empty when every area's words are in the catalog.
Words the window shows from a shared module outside these files, such as a card's own buttons in `src/shared/cards.ts` and the main message's placeholder in `src/shared/firstRun.ts`, are not read yet and move with their own area.

## On the phone

The phone app words itself from the same catalog, compiled a second time into Apple's own string files.
Until every word it shows is in the catalog it ships English alone, so people using the phone see no change yet: iOS cannot ship a language and keep English first.

- `scripts/generate-messages.ts` writes `Localizable.strings` and `Localizable.stringsdict` for each language in `PHONE_LANGUAGES` into `ios/Infinitary/InfinitaryKit/Sources/InfinitaryKit/Resources/<tag>.lproj/`, and `--check` refuses one out of step with the catalogs.
  A blank `{name}` becomes `%N$@` and a plural's count `%N$ld`, where `N` is the blank's place in English's sorted list of blanks, the order `MESSAGE_FILLS` lists them; a plural message is a `.stringsdict` entry whose count picks the form by the language's own rules.
- The same compiler writes `PhoneMessages.generated.swift`: one function per message, as the desktop's compiled file has, such as `PhoneMessages.fileCancel(name:)`.
  A count is an `Int` and groups its digits as the language does, as `formatNumber` writes it.
- A message whose name starts with `phone`, such as `phoneCommonCancel`, is the phone's own: it compiles into the phone's files alone, never the desktop's compiled file, and no saved fact names it.
  Every word the phone's own Swift writes for a person is one of them, a plural one where a count picks the words; the Mac's words it shows are worded apart.
- The phone's three permission prompts are catalog messages too (`PHONE_INFO_PLIST_MESSAGES`): the compiler writes them into `InfinitaryApp/<tag>.lproj/InfoPlist.strings` for each language the phone ships, which iOS shows in the phone's language, and `--check` refuses an `Info.plist` whose English differs from the catalog's.
- `PhoneWords.word(_:)` words a saved fact (`PhoneSaid`, "Saved facts") in the phone's language, filling its blanks in `MESSAGE_FILLS` order, and answers nil for a message the phone's catalog lacks or a blank the fact never filled, so the caller shows the English saved beside it.
- `PhoneFormats` in the same package writes every date, time, age, duration and number the phone shows, in the phone's own locale, its short units worded from the catalog.
- `PhoneWordsTests` replays `Fixtures/PhoneWords.generated.json`, which the compiler writes from the desktop's own `wordSaid`: every message with each blank filled apart, each plural at counts that pick different forms and group digits, and facts no catalog words.
- The phone's journeys find controls by their English words, so `launchPhoneApp` starts the app with `-AppleLanguages (en)` and `-AppleLocale en_US` whatever the simulator speaks.

`node scripts/phone-raw-words.ts` is the phone's raw-words check, run by `pnpm check`.
It reads the Swift under `InfinitaryApp/`, `InfinitaryKit/Sources/` and `PhoneLoadClock/`, generated files aside, and counts each string literal that reads as words by the window's rule, unless it names code: a comparison, a `case` pattern, a dictionary key, an accessibility identifier, a symbol or resource name, script for a web view, or a log line.
Its ledger, `PHONE_RAW_WORDS_LEDGER`, is empty: every word the phone's own Swift writes is in the catalog, and a new one goes there too.
`i18n-exempt: <reason>` in a comment on a literal's line or the line above keeps one typed in, such as a log line or the product's name.
`--show <file>` lists one file's raw words, and `--list` every file's count.

## Right to left

The layout runs both ways: the window and its panels lay out from the start of a line, so a right-to-left language mirrors them.
A stylesheet under the window or the app's own panels names a side by its logical form - `margin-inline-start`, `padding-inline-end`, `border-inline-start`, `border-start-end-radius`, `inset-inline-start` - and aligns text to `start` or `end`; an inline style does the same with React's names, such as `marginInlineStart`.
An inline style's `left` and `right` are coordinates the code measured, such as a pointer's or an orbit's, and stay physical.
A side that must stay physical in a stylesheet says why with `physical: <reason>` in a comment on its line or the line above, such as a box centred with `left: 50%` and `translateX(-50%)`, which mirrors to itself.
The rails stay where a person docked them: a rail on the left stays on the left.
A key's chord in a `<kbd>` reads in the order it is pressed, ⌘ then L, in either direction.
`ar-XB` runs the window right to left, so a layout that assumes left to right shows.

## The checks

`pnpm check` runs these:

- `node scripts/generate-messages.ts --check` refuses a catalog that is not JSON, a message name or placeholder that is not camelCase, a translation that lacks a message or holds one English does not, a translation whose placeholders or count differ from English, a plural message without exactly its language's forms, a hand-written pseudo-language, and a compiled file out of step with the catalogs.
- `node scripts/locale-formats.ts` refuses, outside `src/shared/i18n/`, a fixed `"en-US"` and a `toLocaleString`, `toLocaleDateString`, `toLocaleTimeString` or `Intl` formatter handed no locale, `[]`, `undefined` or a fixed tag.
  Reading `Intl.DateTimeFormat().resolvedOptions()` is allowed: it formats nothing.
  The few places that cannot follow the language are listed in the script with why, and the list only shrinks.
- `node scripts/raw-words.ts` refuses words typed in for a person to read outside its ledger, and a ledger that did not shrink with them ("Words still typed in the code"); `node scripts/phone-raw-words.ts` does the same for the phone's Swift ("On the phone").
- `node scripts/logical-css.ts` refuses a physical side in the window's and the panels' stylesheets and inline styles ("Right to left").
