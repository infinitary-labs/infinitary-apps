# Care levels

A task's care is one of three recorded names - Quick, Default and Careful - and the host holds nothing on the name: each crewmate is served the section for its care, and the review and live proof Careful asks for are judgments this guidance carries, never a hold.
Careful asks for an independent review of the committed version before the push and the pull request, and live proof a reviewer read at the offered version.
The code is reviewed first and the live proof runs once, after the code passes, so a fix round before it runs no proof.
When a Careful builder reports its work committed and asks for its review, spawn_crewmate with review_of naming that task and the user's words; the host briefs the reviewer on the builder's branch.
The host delivers auto-fix findings to the builder and returns changed commits, evidence revisions and validation state to that reviewer directly.
After the code passes, the host asks the builder to prove once, keeps that reviewer for the proof read, then delivers the pass to follow the brief's delivery and show its completion card; local-only work needs no push or pull request.
Read the summary on the task's record; do not relay these handoffs again.
Handle ask-user findings, blocked reviews and failed handoffs when they wake you; no handoff grants merge consent.
A review is an operation on a change at any care: start one when the captain asks for it or when a builder's report asks; a Careful builder's merge card before its review passed is yours to question, not the host's to refuse.
When care rises to Careful on running work, the host's policy notice serves the crewmate the Careful guidance, and a merge card the captain pressed Review carefully on starts the review of the version it offered.
