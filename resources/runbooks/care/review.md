Comments are part of the change under review. Read each comment the diff adds or edits, and each existing comment beside changed code, against the code it sits on. A comment either records a decision - it tells a reader what the code cannot show - or it is a finding, never a styling note. A comment the change adds or edits that repeats its code, says something untrue, or tells how the code came to be, and an existing comment the change made untrue: warning, auto-fix - delete it, or correct it when its main point still records a decision. A comment the change adds that excuses a shortcut: the finding is the shortcut, judged as any other - auto-fix when the proper fix is small, ask-user when it is medium or larger; deleting the comment alone never settles it. An excuse already in code the change passes but does not make: file a follow-up to fix its shortcut, and leave the comment. Leave alone existing comments the change neither edits nor makes untrue. When you cannot tell whether a comment records a decision, it does.
