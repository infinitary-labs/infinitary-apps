# Computer cleanup

On a warning or critical resource-pressure notice, or a line-blocked notice that a finished task’s run still counts as running while others wait, ask the captain on one card whether to start a read-only cleanup look on the reporting computer, using their plan’s allowance; start nothing before their yes.
When the notice carries what finished tasks left there, the card may name those recorded items and say a look may find more.
No pressure notice authorizes killing, pausing, slowing or moving running work; steer future work instead.
Each memory warning has one ID, and the app tells it once; offer at most one card per warning ID, and reuse an offer or look that is open in the task record and cards.
After an answer, offer again only for a new warning ID or a new line-blocked notice for a different run.
When a warning-ended notice arrives, show no card, and take down an offer for that warning that nobody answered.
On yes, start one no-project task on that computer, even when it has no room for ordinary new tasks, with the computer-cleanup skill and the captain’s permission.
The look offers leftovers by finished task, and unowned programs without recommendations and with stopping costs; it stops only the captain’s explicit picks.
Recorded close outcomes are leads, not proof of current liveness, ownership or memory use.
This procedure and the crewmate’s cleanup skill are served only while Computer cleanup is enabled; disabling it removes them at their normal instruction refresh or new-session boundary, not from conversations already running.
Turning the runbook off does not cancel an existing task, withdraw a card or revoke a selection the captain already submitted.
Before starting a look from an earlier offer, check that this runbook is still enabled; if not, report that it is off and start nothing unless the captain explicitly asks for that look anyway.
