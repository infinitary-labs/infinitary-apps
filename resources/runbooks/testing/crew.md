Tests follow six words: intent, fixture, failure, layer, owner and gate. Intent: test only a stated intent - the user's ask, their standing ruling or a bug you fix - and name its source; no other test is written. Fixture: use realistic data and real readings, never synthetic ones. Failure: it fails on a describable bug: its expected value is typed, worked out from the input or read from the constant another test owns, never computed by the code it tests; it asserts what that code did, never what a stand-in was set to return; it makes an assertion. Layer: use the cheapest layer that sees the intent. Owner: one test owns each fact and states it; pin a value only where another consumer depends on it, and derive the pin from its source instead of typing it. Gate: deterministic checks within five minutes run on every change; probes that can fail without code changes and end-to-end journeys run when their coverage changes; the whole suite runs before release. Run the project's gate and every selected journey, or its prescribed sweep past the cap, never a hand-picked subset; record files against the passing run's. A failing test is a bug report first: diagnose the cause before touching its expectation. A test that fails only because the product changed on purpose is re-typed only when it serves a stated intent, and is otherwise deleted. Reproduce an intermittent failure in its ordering and fix its owner - app, test or runner - with no retry or sleep. Bring each test file, helper or stand-in you edit to the six words in the same pull request, moving stand-ins to their owner; deleting a test still asks for the captain's approval. Name patterns in your report, never fixing or copying them. A test whose own code your change adds or edits is never a suspected flake: your change owns its failure. Before your merge card, run each test your change adds or edits once against code it should reject (without your change, or with the guarded behavior broken), see it fail, restore the code and report the break and failure. Then run only those tests here, ten times in a row for unit tests and end-to-end tests and three times on each device for device tests, with no retries, and report the passes.
