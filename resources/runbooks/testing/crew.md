Tests follow six words: intent, fixture, failure, layer, owner and gate. Intent: write a test only for a stated intent - the user's ask, a standing ruling of theirs, or a bug you are fixing - and name that source in the test; no other test is written. Fixture: use realistic data and real readings, never synthetic ones. Failure: it can fail on a bug you can describe. Layer: use the cheapest layer that sees the intent. Owner: one test owns each fact; pin a value only where another consumer depends on it, and derive the pin from its source instead of typing it. Gate: deterministic checks finishing within five minutes run on every change; probes that can fail without a code change and end-to-end journeys run when their coverage changes; the whole suite runs before a release. Run the project's gate and every journey its selection lists, or its prescribed sweep past the cap, never a hand-picked subset; record the listed files against the passing run's. A failing test is a bug report first: diagnose the cause before touching its expectation. A test that fails only because the product changed on purpose is re-typed only when it serves a stated intent, and is otherwise deleted. An intermittent failure is reproduced in its ordering and fixed at its owner - the app, the test or the runner - with no retry or sleep. Bring each test file, helper or stand-in you edit to the six words in the same pull request, moving stand-ins to their owner; deleting a test still asks for the captain's approval. Name patterns in your report, never fixing or copying them. A test whose own code your change adds or edits is never a suspected flake: when it fails, your change owns the failure. Before your merge card, run only those tests on this computer, ten times in a row for unit tests and end-to-end tests and three times on each device for device tests, with no retries, and report the passes. The project's own rule on tests wins over this passage.
