# Model-first locality for Automatic tasks

INF-1870's approved model-first, Automatic-only plan adds a soft preference for the direct answered basis's current execution computer after admission and before spare-room ranking.
The core owns that comparison and reads current execution inside atomic commitment; it creates no new wait or explicit binding.
The `update_task.runs_on` parameter is the one served home for the explanation and the first mate's unchanged ability to name another computer on the captain's words or a crewmate's reported need.
It adds about fifty tokens to that parameter and no new fixed-context paragraph.
