# Review a flagged correction without continuous detection

The approved correction-retention design uses the decision model alone to detect candidates, with project-only offers and relevant guidance to running work.
The `correction-review` wake owns the case-specific instructions to inspect meaning and existing directions, preserve conditions and numbers, and propose only an appropriate lasting instruction.
Routine replies add no detection instruction or candidate report to either agent.
The `correction_case` tool owns reach to the bounded source, independent offer, verified recovery and an agent-declared list of affected workers.
The existing `app_change direction` tool remains the only writer, with its judgment-tier authority over explicit keep requests unchanged.
A keep choice resolves its ordinary card but leaves that offer's independent operation pending until saved-direction readback succeeds.
The fixed prompt is unchanged; the new tool description and parameters add roughly 350 tokens to the first mate's tool surface, not a per-reply detection duty.
A verified save awaiting affected-work judgment uses the same typed case wake without repeating the original conversation.
