# One rule for a crewmate's GitHub calls

FI3-1571 pieces 2 to 4, built as approved: the crewmate asks, and the app adds the exact call and the button; a merge past the rules may skip every rule the captain's account may skip, failed checks included; GitLab follows the same rule; and every write of a task that only answers asks.
A crewmate's `check_change` takes `skipRules` with `pull`: a GitHub merge past the branch rules at the version it read, which `request_merge` names and only the captain's click sends, once.
`github_read` reaches whatever the sign-in may read, with no read list; GraphQL stays refused.
`github_write` keeps every write outside the task's own project, every write of a task that only answers, and every write through the github.com sign-in, and answers with an ask id.
A crewmate's `emit_card` action may carry `request_write` naming that id; the host draws the exact call, names the button after the host, and only the captain's click sends it, once, waking the crewmate with the answer.
The crewmate's own `actions` parameter names the new effect; the Firstmate's `emit_card`, prompt and wakes are unchanged, so its fixed context does not grow.
