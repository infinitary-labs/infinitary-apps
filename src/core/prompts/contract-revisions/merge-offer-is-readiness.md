# The merge offer expresses readiness

INF-1555 F12 replaces the separate ready/red requirement: the captain says that a crew's merge offer itself means the work is ready.
The rule's one served home is the `check_change` description in `src/core/pi/forgeTools.ts`, including the unchanged boundary that an offer is not captain consent.
That tool retains evidence-backed flake and explicit repair settlement declarations, not a second readiness record.
The core projects only actual check facts in `ciFact.ts`, task facts and merge holds; check-observation wakes point to current facts and the existing delivery guidance rather than asking for a separate verdict.
F13 keeps the crew-owned positive no-checks declaration unchanged, and F14 preserves an unreadable-list reason with the facts.
No fixed first-mate context is added; its recorded-check sentence loses the separate verdict.
The crewmate delivery exception retains finished-check diagnosis and the captain’s separate merge choice, without the retired red-declaration prerequisite.
