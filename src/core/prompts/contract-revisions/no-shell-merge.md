# A merge is never an operation

INF-4362, filed from INF-4360: after GitHub refused a clicked merge for a branch rule and the captain asked for an admin merge in words, the first mate filed the merge as an operation.
An operation has no merge card, so its crewmate merged the pull request from its shell with a command-line sign-in, past the rule and without the card that names each rule and records the captain's click.
INF-4360's direction A steers only the kept-merge wait to the skip card, and only when the host could read the sign-in's right to skip.
Now `spawn_crewmate`'s `constraints` description, which `create_task`'s points to, says an operation has no merge card, so it is never a merge nor a merge card to prepare: the first mate steers the crewmate whose task owns the pull request to its merge card, past the branch rules with `check_change skipRules`, or starts one of another kind.
Its one home is that top-level parameter's description; the core is unchanged.
The crewmate's own half, never to merge a pull request or push to a default branch from its shell, is the crewmate prompt's identity paragraph, which every kind of task is served; it is not part of this contract.
The fixed context grows by about 52 tokens, in that one description.
