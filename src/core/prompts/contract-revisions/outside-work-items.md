# Outside work items

INF-6845's approved plan, piece 1; the captain chose "Approve and build" after asking that the runbook "just focus on how to handle externally stored work items", instructions only, with no structured link saved on tasks.

What the first mate is now told:

- The built-in runbook Outside work items, on by default, serves a first-mate guide: an outside work item is an issue, ticket, request or report kept outside the app; a task reading one strangers can write to starts as an unsafe data reader; work on an item gets one side-effect task whose words name the item's address, filed with `create_task` `side_effect`, `blocked_by`, the read-only constraint and, where strangers write, `unsafe_data_reader`, and naming the moment it tells the item, after searching tasks for an open one to join; the item hears the ending at the first release that ships the work, or at its merge where the project publishes no releases.
- `create_task` takes `unsafe_data_reader`, pointing to `spawn_crewmate`'s shape field for its rule; it is refused with nothing filed on work that is not an answer or on the personal workspace, as a spawn is.

What a crewmate reads: the runbook's crew section, selected by the new `sideEffect` selector, reaches only a side-effect task, and says how to reply once and close the item the tracker's own way. Every side-effect task's brief also lists each finished wait's reported summary and typed result, or under a reader's wait its report itself, between the reader-data marks it was saved with. Every write a side-effect task makes where a project lives, but a run start or rerun on its own, now waits for the captain's click, and its refusal says so.

Homes: the reader rule stays on `spawn_crewmate`'s `unsafe_data_reader`; the filing rule stays in HANDOFF; the runbook's guide holds only what is particular to an outside item.
The guide costs about 360 tokens of the first mate's runbook guidance while the runbook is on, and the new parameter about 15 tokens of tool surface.
The host keeps only typed facts: the side-effect mark, which holds its writes, the reader mark and each wait's own report; the item's address lives in the side-effect task's words.
