# One path for project changes

The accepted FI3-1570 choice is “On my words, or my click on a card the app writes: one path for every change”, with the written-in scope “everything that the user can change through UI”.
Firstmate's project-settings and project-runs-on apply an exact change named in a captain message or captain-set schedule; every other proposal gets an app-written exact-change card instead of a refusal.
An ordinary agent-authored card choice is no longer authority to apply a different project patch.
The app's Apply change button uses the stored patch once, refuses changed underlying values, and runs the dispatcher Settings uses.
Where it lives always gets that card, because git's mutable address must not silently move the task's API write fence.
Project-settings adds name, path for an already moved folder, and origin for the current git address; keys, task history, setup provenance and workspace kind remain fixed.
Removal still requires the captain's typed words, and adding still uses the setup card.
The project-change wake tells Firstmate the outcome once, not permission for another change.
Firstmate declares exact captain words with the optional `on_words` boolean; omitting it proposes even on a captain turn.
Tool guidance owns the exact-words judgment; the host never tries to parse natural language.
The app_change guidance is shortened to pay for the new declaration within the existing fixed-context budget.
