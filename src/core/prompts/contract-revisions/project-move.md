# Moving repositories between projects

INF-5005's plan, approved with "keep each task's key", adds the catalog action `project-move`: repositories join another project in one step, keeping each repository's name, folder and settings, with their tasks keeping their keys.
It amends INF-4220's answer that a repository changes project only by being removed and added again.
`project-move` is the third project change on the one path for project changes: exact captain words with `on_words` apply it at once, and otherwise the app writes its move card, whose Apply move applies it once.
Its home is its catalog line, which the first mate reads through `app_state`: what `repoIds` and `project` take, what stays and what follows, and that projects are combined by moving, never by removing and adding back.
`project-remove`'s line and `project-setup`'s line each point to the move in one clause.
The `app_change` description names `project-move` beside the other two `on_words` actions and says the card applies the change once in fewer words, so the fixed context does not grow.
The `project-change` wake is unchanged: the first mate hears the move card's outcome once, by its title.
