# Settings parity actions

INF-5354, the first piece of INF-5326's approved plan, gives the first mate what a person can do in Settings through the same requests, wherever no ground keeps it the captain's.
The first mate is told, in each action's own description in the catalog `app_state` serves, about the new and widened actions: ambient music plays again after a pause, card size, language, usage unit, a panel's More pick and a full reset, model pins' restore, and Settings' own buttons for the update channel and check, the inbox link, a panel's retry and ask again, a decision model use off, keeping a device, cancelling a home move, stopping a copy, fixing or retrying a work computer, removing a private site, ending a secret read and checking a kept job.
Each rule's one home is its action's description in that catalog; `dictation`, `panel-retry`, `private-site-remove` and `secret-end-read` join the own-words list the `app_change` description names.
The `app_change` tool's answer gains an optional `answer` field, an act's own result, beside `action` and `current`.
The captain's pick on the review, to let the first mate target the paired Mac, adds a `key-reminders` action, `window: true` on each `app_state` line that is a window's own setting, and an optional top-level `computer` parameter on `app_change`, whose one home is that parameter's description: for a window's own setting it names the Mac that controls this one whose window the captain means, and omitted it means this computer.
The fixed context grows by those four names in the `app_change` description and the `computer` parameter's one sentence, a few dozen tokens; the catalog itself is read through `app_state`.
