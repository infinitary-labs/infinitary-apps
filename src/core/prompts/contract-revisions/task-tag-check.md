# Checking tasks for tags

The third piece of an approved plan for tags on tasks: the decision model tags each new task in a project with tags on its own, and Check existing tasks backfills a project's older tasks.
The new project-tag-check action line owns starting and stopping a check on the captain's ask: its words name the reaches (open, open and done in the last 7 days, every task), that a check spends one decision model request per task, that stop keeps every answer so far and that one check runs at a time; its current value lists each project with tags, how many requests each reach would make, who answers and the check under way.
The first mate is told nothing about automatic tagging itself: the host runs it, and tags a person or the first mate set are never changed by it.
The line adds about 90 tokens where action lines are served, and its name joins app_change's action list.
