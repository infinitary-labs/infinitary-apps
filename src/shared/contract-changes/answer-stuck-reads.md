# Answer stuck reads

A new order, `inf:session:answer-reads`, asks a computer that runs work to answer "ask again" each of the app's own reads a task's conversation began by the newest event the home has taken (`through`), and answers which reads it answered and how long each waited.
The home asks it at the quiet watchdog's twenty-minute check, so a turn stuck in a read that never returns goes on and reads the steers queued behind it.
A home never sends it to a computer that does not list this change: such a computer's reads wait as before, and the home's quiet alert names the open call instead.
