A home answers a paired view every request whose `reach` is `views`, and that set now holds every request a view of a first mate started by a command could ask, whatever started the first mate.
What stays on the first mate's computer is a request whose `reach` is `home`.
A home lists this change and sends `startedByCommand: true` only in the welcome to a view that does not list it, so a view from before this change still asks the wider set; the next major removes the field.
A page the first mate would open for a view's request goes to the views as `inf:app:open-page`.
Once a view's window knows that its home does not list this change, it does not ask that home the wider set, and says the home needs an update.
A read a window makes as it first opens, before it knows, can still reach that home, which refuses or answers it under its old rule.
